# apps/web — веб-клиент Datascratch

Полноценная замена десктопа (D-02, D-03): Vite + React + TypeScript, PWA (офлайн, установка), без SSR. Поток: web-app (D-39). Стек — `docs/architecture/stack.md`; форматы и протоколы — контракты `docs/architecture/contracts/`.

**Статус:** работает весь основной путь — регистрация с ключом восстановления, вход, восстановление, смена пароля, устройства; пространства → блокноты → папки (D-36), списки и сетка документов, вкладки, ⌘K, контекстные меню, перетаскивание; экран документа (обложка — зашифрованное вложение, стиль, подложка, значок, бэклинки, история версий с откатом); задачи и календарь с ежедневными заметками (spec/12); шеринг по ссылке и гостевой маршрут с правкой и присутствием (D-13, D-37); настройки блокнотов (режим «для агентов» с честным предупреждением), токены агентов, тема и язык. Офлайн-работа и синхронизация проверены e2e-тестами против мок-сервера.

## Запуск

```bash
pnpm install                      # из корня репозитория
cd apps/web
pnpm mock-server                  # мок-сервер API и синхронизации на :8787 (пока нет apps/server)
VITE_DS_SERVER_URL=http://localhost:8787 pnpm dev
```

Адрес сервера — переменная окружения `VITE_DS_SERVER_URL` (по умолчанию — тот же адрес, что у веб-приложения). Сборка сервер не требует: `pnpm build`.

| Команда | Что делает |
| --- | --- |
| `pnpm typecheck` | Проверка типов |
| `pnpm test` | Unit-тесты (vitest): крипто-заглушка, модель документа, протокол синхронизации, паритет переводов |
| `pnpm e2e` | Playwright: production-сборка с service worker + мок-сервер. Нужна свежая `vite build` (`pnpm e2e:build` делает обе) |

CI — `.github/workflows/web.yml`.

  api/          REST-клиент (api.md) с обновлением токена

                индекс задач и поиска, рантайм аккаунта, гостевая сессия, присутствие
  sync/         движок синхронизации по WebSocket (sync-protocol.md)

### Данные на устройстве (офлайн-первый, spec/10)

- **IndexedDB через Dexie.** База устройства `ds-device` (идентификатор устройства, неизвлекаемый ключ WebCrypto, сессия) и база аккаунта `ds-account-<userId>`: строки документов (`lastSeq`, регистрация на сервере), обновления Yjs, исходящая очередь (уже зашифрованные `push`/`snapshot`), очередь REST-операций, индекс задач, индекс заметок (текст, теги, ссылки).
- **Ключи.** Мастер-ключ — только в памяти; между перезагрузками хранится зашифрованным неизвлекаемым AES-ключом WebCrypto (браузер не отдаёт его байты даже скриптам этого сайта). Ключи блокнотов кешируются в виде, обёрнутом мастер-ключом; ключи заметок разворачиваются из индекса блокнота. На сервер не уходит ни один ключ, кроме ключа блокнота в режиме «для агентов» (crypto.md §8).
- **Выход** удаляет базу аккаунта с устройства.

### Синхронизация

- Каждый документ (`account`, `notebook`, `note`) — Y.Doc; локальная правка сразу пишется в IndexedDB и, зашифрованной, в исходящую очередь.
- Порядок при подключении: очередь REST-операций (создание блокнотов, регистрация документов `POST /v1/docs`) → `hello` → подписка: аккаунт, затем блокноты, затем заметки (ключи «текут» сверху вниз) → отправка очереди. Неподтверждённое (`ack`) не удаляется.
- `lastSeq` продвигается только по непрерывной последовательности; дубликаты безвредны (CRDT).
- Снимок (`snapshot`) — после 500 обновлений (sync-protocol.md §5) и при уходе из документа после ≥ 30 правок (для истории версий, см. «Вопросы»).
- Статус — индикатор в боковой панели: синхронизировано / синхронизация / офлайн + число неотправленных изменений.

### Производные данные (document-model.md §5)

Индексатор после правок (с задержкой 0,6 с) разбирает заметку: заголовок, текст, задачи, ссылки `[[ ]]`, теги. Результат — таблицы `tasks` и `noteIndex` и поиск MiniSearch в памяти. Заголовок и теги копируются в `NoteMeta` индекса блокнота для списков.

### Вложения (crypto.md §6)

Файл режется на куски по 1 МиБ, каждый — отдельный конверт с ключом заметки и `ad` с индексом и признаком последнего. Зашифрованные куски сначала сохраняются в IndexedDB (работает офлайн), затем докачиваются в фоне по одному (`POST /v1/attachments`, `PUT …/chunks/:i`). Обложка хранится в `meta.cover` заметки (2400 px), миниатюра для карточек — в `NoteMeta.coverThumb` (640 px).

### Гости (D-13, D-37)

`/s/:shareId#k=<ключ>`: ключ берётся из части после `#` и на сервер не уходит. Гостевая сессия живёт только в памяти: `POST /v1/shares/:id/guest` → гостевой токен → синхронизация как у владельца, но без IndexedDB. С правом правки гость пишет и рисует; присутствие (курсоры, «Гость») шифруется ключом документа.

### Пакеты других потоков

- `@datascratch/shared` (core) — крипто, идентификаторы, типы контрактов; подключён через `src/lib/shared.ts` (асинхронные обёртки, которые сами инициализируют libsodium).
- `@datascratch/web-editor` — редактор с пером (`DatascratchEditor`); приложение передаёт ему `EditorHost` (`src/editor/hosts.ts`): вложения, ссылки `[[ ]]`, карточки, теги, действия задач.
- `@datascratch/ui` и `@datascratch/design-tokens` (design-system) — компоненты, токены и шрифты; `src/ui/` — тонкий слой композиции (меню как данные, диалоги, императивные тосты).
- Синхронизация пока своя (`src/sync/engine.ts`, протестирована e2e); переход на `SyncClient` из shared — отдельным шагом.

E2E можно прогнать и против настоящего сервера: собрать с `VITE_DS_SERVER_URL=http://localhost:8080` и запустить `E2E_SERVER_URL=http://localhost:8080 pnpm e2e` (в CI это отдельный джоб с PostgreSQL).
