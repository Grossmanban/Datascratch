# apps/web — веб-клиент Datascratch

Полноценная замена десктопа (D-02, D-03): Vite + React + TypeScript, PWA (офлайн, установка), без SSR. Поток: web-app (D-39). Стек — `docs/architecture/stack.md`; форматы и протоколы — контракты `docs/architecture/contracts/`.

**Статус:** работает весь основной путь — регистрация с ключом восстановления, вход, восстановление, смена пароля, устройства; пространства → блокноты → папки (D-36), списки и сетка документов, вкладки, ⌘K, контекстные меню, перетаскивание; экран документа (обложка — зашифрованное вложение, стиль, значок, бэклинки, история версий с откатом); задачи и календарь с ежедневными заметками (spec/12); шеринг по ссылке и гостевой маршрут с правкой и присутствием (D-13, D-37); настройки блокнотов (режим «для агентов» с честным предупреждением), токены агентов, тема и язык. Офлайн-работа и синхронизация проверены e2e-тестами против мок-сервера.

## Запуск

```bash
pnpm install                      # из корня репозитория
cd apps/web
pnpm mock-server                  # мок-сервер API и синхронизации на :8787 (для e2e; против настоящего сервера — `E2E_SERVER_URL`)
VITE_DS_SERVER_URL=http://localhost:8787 pnpm dev
```

Адрес сервера — переменная окружения `VITE_DS_SERVER_URL` (по умолчанию — тот же адрес, что у веб-приложения; так веб и разворачивается: `infra/deploy`, один домен с API). Service worker не перехватывает переходы на серверные пути общего домена (`/v1/`, `/mcp`, `/oauth/`, `/.well-known/` — `src/lib/serverPaths.ts`), иначе страница согласия OAuth для агентов открывалась бы как приложение. Сборка сервер не требует: `pnpm build`.

| Команда | Что делает |
| --- | --- |
| `pnpm typecheck` | Проверка типов |
| `pnpm test` | Unit-тесты (vitest): модель документа, хранилище синхронизации и миграция IndexedDB, паритет переводов, `/connect` |
| `pnpm e2e` | Playwright: production-сборка с service worker + мок-сервер. Нужна свежая `vite build` (`pnpm e2e:build` делает обе) |

CI — `.github/workflows/web.yml`. Сборка для e2e против мок-сервера идёт с `VITE_DS_TEST_HOOKS=1`: тест производительности (`e2e/specs/perf.spec.ts`) получает доступ к рантайму через `window.__ds`, чтобы подложить 10 000 заметок. Обычная сборка этот доступ не открывает.

## Как устроено

```
src/
  app/          маршруты (TanStack Router) и корневой компонент
  auth/         вход, регистрация, восстановление (crypto.md), хранение сессии
  api/          REST-клиент (api.md) с обновлением токена
  data/         локальная база (Dexie), документы Yjs, ключи, очередь операций,
                индекс задач и поиска, рантайм аккаунта, гостевая сессия, присутствие
  sync/         статус синхронизации для интерфейса
  domain/       модель документов (document-model.md) и действия над ней
  features/     экраны: auth, shell (боковая панель), docs, doc, tasks, calendar,
                settings, share, guest, palette
  lib/ ui/ editor/ i18n/ styles/
e2e/            Playwright-тесты и мок-сервер
```

### Гибкий интерфейс

- Боковая панель скрывается кнопкой или ⌘\ и остаётся скрытой после перезагрузки; свёрнутая панель `inert` (не ловит Tab).
- «На весь экран» для документа, календаря и задач — кнопка в верхней панели или ⌘⇧F; запоминается отдельно для каждого вида экрана (`ds.focus.*`), настройку панели не меняет.
- Явное закрытие вкладки документа — кнопка × в верхней панели документа или ⌥W (⌘W закрывает вкладку браузера); открывается следующая вкладка или «Все документы».
- Ключ плавного перехода между экранами берётся из `resolvedLocation` — иначе на миг монтировался предыдущий экран (и документ заново открывал свою вкладку). e2e `layout.spec.ts`.

### Сессия в нескольких вкладках

Сервер считает повторное предъявление уже использованного refresh-токена кражей и отзывает устройство. Вкладки приложения делят одну сессию, поэтому обновление токена идёт под межвкладочной блокировкой (Web Locks), а вкладка, обнаружившая, что другая уже обновила сессию, берёт её результат из IndexedDB (e2e `session.spec.ts`; мок-сервер повторяет поведение сервера). Сессия сохраняется на устройство до того, как приложение откроется после входа, — перезагрузка сразу после входа не возвращает на экран входа.

### Ключ восстановления (spec/07)

- После регистрации — экран ключа: копировать, скачать, подтвердить (последние 4 символа). Подтверждение **необязательное**: «Пропустить» с коротким предупреждением.
- Ключ хранится только на устройстве, где создан (запечатан неизвлекаемым ключом устройства, как masterKey; решение координатора — вариант А), и показывается там в «Настройки → Аккаунт → Ключ восстановления».
- Подтверждение — флаг `settings.recoveryKeyConfirmed` документа аккаунта (`document-model.md`): напоминание (карточка и точка на значке настроек) видно и исчезает на всех устройствах. Экран регистрации работает до синхронизации аккаунта, поэтому отметка сначала пишется на устройство и переносится в документ (`auth/recovery.ts`).
- «Создать новый ключ» — на любом устройстве, с паролем (`POST /v1/auth/recovery-key`, `rotateRecoveryKey` из shared): старый ключ сразу перестаёт работать, флаг сбрасывается, новый ключ показывается и хранится на этом устройстве. Устройство со старым ключом узнаёт о замене из журнала безопасности и забывает его.
- Журнал безопасности (`GET /v1/me/security-events`) — в карточке «Устройства».

### Данные на устройстве (офлайн-первый, spec/10)

- **IndexedDB через Dexie.** База устройства `ds-device` (идентификатор устройства, неизвлекаемый ключ WebCrypto, сессия) и база аккаунта `ds-account-<userId>`: строки документов (`lastSeq`, регистрация на сервере), обновления Yjs, исходящая очередь (уже зашифрованные `push`/`snapshot`), очередь REST-операций, индекс задач, индекс заметок (текст, теги, ссылки).
- **Ключи.** Мастер-ключ — только в памяти; между перезагрузками хранится зашифрованным неизвлекаемым AES-ключом WebCrypto (браузер не отдаёт его байты даже скриптам этого сайта). Ключи блокнотов кешируются в виде, обёрнутом мастер-ключом; ключи заметок разворачиваются из индекса блокнота. На сервер не уходит ни один ключ, кроме ключа блокнота в режиме «для агентов» (crypto.md §8).
- **Выход** удаляет базу аккаунта с устройства.

### Синхронизация

- Протокол ведёт `SyncClient` из `@datascratch/shared/sync`; веб даёт ему хранилище `DexieSyncStorage` (`src/data/syncStorage.ts`: таблицы `syncDocs` и `syncOutbox`, пакетные `getDocStates`/`setDocStates` одной транзакцией Dexie).
- Документы `account` и `notebook` (индексы) — живые Y.Doc. Заметки синхронизируются в «хранимом» режиме `SyncClient` (`storedDocs`): чужие обновления сливаются в сохранённое состояние в IndexedDB (`DocStore.appendStored`), Y.Doc создаётся только пока заметку держат (открытый редактор, действие) — `openDoc`/`closeDoc` через `DocStore.acquire`/`release`. При 10 000 заметок в памяти 2 документа вместо 10 003 (e2e `perf.spec.ts`: куча после GC 72 МБ вместо 139 МБ).
- Локальная правка сразу пишется в IndexedDB (`updates`), а `SyncClient` шифрует её и кладёт в исходящую очередь. Неподтверждённое (`ack`) не удаляется.
- Новый документ сначала регистрируется REST-очередью (`POST /v1/docs`), затем подключается к клиенту; если регистрация прошла позже — `resubscribe`.
- Миграция базы v3→v4 переносит старую исходящую очередь в `syncOutbox` — неотправленные правки не теряются.
- Снимок (`snapshot`) — автоматически в `SyncClient` и при уходе из документа после ≥ 30 правок (`requestSnapshot`, для истории версий).
- Браузер не всегда закрывает WebSocket при потере сети, поэтому по событию `offline` клиент переподключается сам.
- Статус — индикатор в боковой панели: синхронизировано / синхронизация / офлайн + число неотправленных изменений.

### Перенос заметки в другой блокнот

Пункт «Переместить в блокнот…» в контекстном меню документа (api.md, «Перенос заметки»): общий хелпер `moveNoteToNotebook` из `shared` переоборачивает ключ заметки ключом нового блокнота, пишет `NoteMeta` в его индекс, вызывает `PATCH /v1/docs/:id` и удаляет запись из старого индекса (при ошибке — откат). Нужна сеть: офлайн перенос не ставится в очередь, пользователь видит подсказку. Перенос в блокнот «для агентов» из личного — с честным предупреждением, что сервер сможет читать документ. Вложенные под неё заметки остаются в старом блокноте на верхнем уровне.

На других устройствах заметка не отключается от синхронизации, пока её запись есть хотя бы в одном индексе; ключ ищется в том блокноте, который её сейчас содержит.

### Большие списки (10 000 заметок)

- Списки и сетка документов виртуализированы (`@tanstack/react-virtual`): в DOM — только видимые карточки (≈30 вместо 10 000), сетка считает колонки по ширине.
- Снимок рабочего пространства (`refreshNotebook`) сохраняет неизменённые записи по ссылке, а неизменённую карту заметок — целиком; карточки обёрнуты в `memo`, поэтому правка одной заметки перерисовывает одну карточку.
- Форматтеры дат `Intl` кешируются (раньше создавались на каждую карточку — это была главная задержка).
- Сниппеты читаются из индекса только для видимых карточек.
- Замеры (e2e, 10 000 заметок, Chromium): правка заголовка — ~45 мс (было 8,5 с), прокрутка в конец — ~30 мс, холодный старт — ~0,7 с. Пороги зашиты в тест.

### Обложка (spec/12 §12.7)

- Только своё изображение: «…» → «Обложка…» открывает окно, куда изображение можно перетащить, вставить из буфера (⌘V) или выбрать файлом; картинку можно бросить и прямо на существующую обложку. Готовых градиентов нет, по умолчанию обложки нет.
- Шапка компактная (150 px на телефоне, 190 px на компьютере), кадр сдвигается.
- Карточка документа — `DocCard asChild` из `@datascratch/ui` (корень — ссылка роутера, её доступное имя — заголовок и отрывок): миниатюра обложки (`coverThumb`, расшифровывается на лету; до этого — заглушка того же размера), без обложки — компактная карточка со значком. Переключатель пространств — `SpaceTile`. В списке миниатюра — вместо значка.
- `meta.backdrop` в интерфейсе не предлагается (существующую подложку документ по-прежнему показывает).

### Доступность и вид

- e2e `a11y.spec.ts` (axe-core, WCAG 2.1 AA): вход, все документы, задачи, календарь, настройки, документ — светлая и тёмная тема, телефон; падает на серьёзных и критичных нарушениях.
- Значимый мелкий текст (счётчики, даты, заголовки разделов) — цвет `text.secondary`; `text.tertiary` (контраст ≈ 2,7 на «бумаге») — только для иконок, плейсхолдеров и выполненных задач, как и задумано контрактом токенов («подсказки»).
- Кнопки, видимые по наведению, появляются и при фокусе с клавиатуры; у кнопок-иконок есть подписи; вкладки задач и настроек на телефоне показывают только иконку, но подпись остаётся для экранного диктора (`sr-only`), активная помечена `aria-current`.
- e2e `keyboard.spec.ts`: документ открывается только с клавиатуры, у каждой остановки фокуса видимое кольцо; ⌘K/Escape.
- Тема переключается мгновенно на всех экранах (e2e `theme.spec.ts` ищет крупные поверхности, не сменившие цвет, и проверяет контраст диалогов, меню и палитры команд в тёмной теме). Выбранный день календаря — акцентным цветом (раньше — инверсия «чернил», яркое пятно в тёмной теме).
- По дизайн-ревью (design-system): верхняя панель — часть «бумаги» (полупрозрачный холст с размытием, без тени; тонкая линия только при прокрутке); заголовки секций — обычный регистр; даты — с заглавной только первая буква, без «г.»; выбранный день календаря — мягкая заливка, «сегодня» — красная цифра; карточки настроек — без внешней тени.
- Движение: короткий переход при смене экрана; все анимации (motion и CSS) следуют системной настройке «уменьшить движение» (`MotionConfig reducedMotion="user"` и медиазапрос). Пустые списки не показывают «0 документов» над пустым состоянием.
- Палитра пера редактора прижата к низу экрана даже в короткой заметке (редактор растягивается на страницу), на телефоне листается внутри экрана.

### Производные данные (document-model.md §5)

Индексатор — `createNoteIndexer` из shared (пакеты по 100, задержка 0,4 с): разбирает заметку из сохранённого состояния на временном Y.Doc (заметки не держатся в памяти), пакет пишется одной транзакцией Dexie: заголовок, текст, задачи, ссылки `[[ ]]`, теги. Результат — таблицы `tasks` и `noteIndex` и поиск MiniSearch в памяти. Заголовок и теги копируются в `NoteMeta` индекса блокнота для списков.

### Вложения (crypto.md §6)

Файл режется на куски по 1 МиБ, каждый — отдельный конверт с ключом заметки и `ad` с индексом и признаком последнего. Зашифрованные куски сначала сохраняются в IndexedDB (работает офлайн), затем докачиваются в фоне по одному (`POST /v1/attachments`, `PUT …/chunks/:i`). Обложка хранится в `meta.cover` заметки (2400 px), миниатюра для карточек — в `NoteMeta.coverThumb` (640 px).

### Гости (D-13, D-37)

`/s/:shareId#k=<ключ>`: ключ берётся из части после `#` и на сервер не уходит. Гостевая сессия живёт только в памяти: `POST /v1/shares/:id/guest` → гостевой токен → синхронизация как у владельца, но без IndexedDB. С правом правки гость пишет и рисует; присутствие (курсоры, «Гость») шифруется ключом документа.

### Пакеты других потоков

- `@datascratch/shared` (core) — крипто, идентификаторы, типы контрактов; подключён через `src/lib/shared.ts` (асинхронные обёртки, которые сами инициализируют libsodium).
- `@datascratch/web-editor` — редактор с пером (`DatascratchEditor`); приложение передаёт ему `EditorHost` (`src/editor/hosts.ts`): вложения, ссылки `[[ ]]`, карточки, теги, действия задач.
- `@datascratch/ui` и `@datascratch/design-tokens` (design-system) — компоненты, токены и шрифты; `src/ui/` — тонкий слой композиции (меню как данные, диалоги, императивные тосты).
- Синхронизация — `SyncClient` из `@datascratch/shared/sync` с хранилищем на IndexedDB.

E2E можно прогнать и против настоящего сервера: собрать с `VITE_DS_SERVER_URL=http://localhost:8080` и запустить `E2E_SERVER_URL=http://localhost:8080 pnpm e2e` (в CI это отдельный джоб с PostgreSQL).
