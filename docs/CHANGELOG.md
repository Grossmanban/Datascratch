## 2026-10-25 (вторая половина дня)

- 2026-10-26 — **server:** повтор `POST /auth/refresh` с тем же токеном в течение 60 с, пока выданный взамен токен не использован, возвращает тот же новый токен вместо отзыва устройства: потерянный в нестабильной сети ответ больше не отключает устройство. Повтор позже или после использования нового токена — по-прежнему отзыв. Контракт `api.md`, тесты на настоящем PostgreSQL.
- 2026-10-26 — **server:** при `subscribe` с `since` меньше `seq` последнего снимка сервер всегда присылает этот снимок и обновления после него, даже если промежуточные обновления ещё хранятся (sync-protocol §5): клиент, не читающий часть обновлений, восстанавливается по исправному снимку. Тест на настоящем PostgreSQL.
- 2026-10-26 (ios-core) — DSCore: устойчивость к зависающим TLS-рукопожатиям — один `URLSession` на REST и WebSocket (переиспользование соединений), короткие тайм-ауты попыток и повторы с разбросом (любой запрос — если точно не ушёл, идемпотентные — и после тайм-аута/502–504; обновление токена после тайм-аута не повторяется: одноразовый refresh-токен), тайм-аут рукопожатия WebSocket и два быстрых переподключения до экспоненциальной задержки; статус остаётся «Синхронизация…», пока идут повторы.
