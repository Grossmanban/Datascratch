# Документация Datascratch

Эта папка — **единственный источник истины** о проекте. Она написана так, чтобы человек или ИИ, впервые открывший репозиторий, понял проект целиком, не видя ни одного чата.

## Порядок чтения для новичка

1. `spec/01-concept.md` — что это за продукт и зачем (5 минут).
2. `roadmap.md` — какие этапы, где мы сейчас.
3. `architecture/stack.md` — на чём пишем и почему.
4. `architecture/overview.md` — как устроена система целиком (схемы).
5. `spec/03-pencil.md` — ключевая фича и главный риск: перо в тексте.
6. `decisions/README.md` — таблица всех решений со статусами.
7. `open-questions.md` и `risks.md` — что не решено и что может пойти не так.
8. `development.md` — как устроена работа: облако + Mac, Graphify, CI.
9. Последний файл в `history/` — что делали в прошлой сессии.

Остальные разделы ТЗ (`spec/`) читаются по мере надобности.

## Соглашения

### Статусы

- **РЕШЕНО** — подтверждено пользователем. Не пересматривается без его согласия.
- **ПРЕДЛОЖЕНО** — рекомендация Claude, пользователь ещё не подтвердил.
- **ОТКРЫТО** — нужно обсудить.

Статус ставится у каждого решения (в ADR) и у спорных пунктов ТЗ (в тексте пометкой).

### Ссылки на решения

Решения нумеруются `D-NN` (так они называются в обсуждениях) и лежат в файлах `decisions/00NN-название.md`. В тексте ТЗ ссылаемся как «(D-05)».

### Как вносить изменения

Любое изменение требований, архитектуры или решения — **в одном коммите**:

1. обновить раздел в `spec/` и/или `architecture/`;
2. создать или обновить ADR в `decisions/` (шаблон — `decisions/0000-template.md`) и строку в `decisions/README.md`;
3. добавить строку в `CHANGELOG.md`;
4. при необходимости обновить `roadmap.md`, `open-questions.md`, `risks.md`;
5. обновить граф Graphify (`tools/graphify_docs.py`, см. `development.md`) и закоммитить его вместе с изменениями.

Решение со статусом РЕШЕНО не переписывается задним числом: если пользователь его меняет, ADR получает статус «ЗАМЕНЕНО решением D-NN», а новое решение оформляется отдельным ADR.

### История

`history/` — архив, а не источник истины. Передаточный документ `history/2026-10-25-handoff.md` сохранён без изменений; в части стека он **устарел** (там ещё Redis и MinIO, стек «предложен»). В конце каждой рабочей сессии добавляется файл `history/ГГГГ-ММ-ДД-session-NN.md`.

`history/` исключена из графа Graphify (`.graphifyignore`), чтобы граф показывал только актуальное состояние.
