# Контракт: API для ИИ-агентов — MCP, REST, OAuth (v1)

> Статус: **v1 — предложен потоком agents и утверждён координатором 2026-10-25.** Реализация: `packages/agents` (Fastify-плагин `@datascratch/agents`).
>
> Связано: D-04, D-09, D-10, D-11, R-10, R-13, `spec/09-agents-api.md`, `api.md` (токены агентов), `document-model.md`, `strokes.md`, `crypto.md` §8.

## 1. Как устроено

Плагин подключается сервером в свой процесс (`app.register(agentsPlugin, { context, publicUrl, secret })`) и регистрирует маршруты по абсолютным путям:

| Путь | Что | Кто вызывает |
| --- | --- | --- |
| `/mcp` | MCP-сервер, Streamable HTTP | MCP-клиенты (Claude, ChatGPT, Cursor…) |
| `/.well-known/oauth-protected-resource[/mcp]` | Метаданные ресурса (RFC 9728) | MCP-клиенты |
| `/.well-known/oauth-authorization-server` | Метаданные сервера авторизации (RFC 8414) | MCP-клиенты |
| `/oauth/register`, `/oauth/authorize`, `/oauth/token`, `/oauth/revoke` | Сервер авторизации OAuth 2.1 | MCP-клиенты, браузер пользователя |
| `/v1/agent/*` | REST для агентов без MCP (те же операции) | скрипты, агенты |
| `/v1/agent-tokens…` | Управление доступом агентов (из `api.md`) | iOS, веб (пользователь) |

Слой MCP — тонкий адаптер над общим сервисом (`AgentService`); REST вызывает те же функции (R-13).

**MCP.** Официальный TypeScript SDK **v2** (`@modelcontextprotocol/server` 2.4, спецификация **2026-07-28**). Обработчик без состояния (новый экземпляр сервера на запрос), клиенты 2025 года обслуживаются автоматически через совместимый путь SDK. Проверка `Origin` (защита от DNS-rebinding): запросы с чужим `Origin` → 403; без `Origin` (серверные клиенты) — разрешены.

## 2. Доступ

- Агенту доступны **только** блокноты в режиме «для агентов» (D-04) **и** только перечисленные в его разрешении. Проверяется на каждом запросе: перевод блокнота в приватный режим мгновенно закрывает доступ.
- Заметки в корзине (`trashedAt`) агенту не видны.
- Права: `read` (поиск, чтение) и `read_write` (+ создание, правка, комментарии, задачи).
- **Разрешение (grant)** — то, что пользователь позволил агенту. Два вида: `static` (токен, созданный в настройках) и `oauth` (согласие на экране OAuth). Отзыв разрешения сразу делает недействительными все его токены.
- Дублирование прав в PostgreSQL Row-Level Security — задача потока server (запросы плагина к БД идут через `context`).

### 2.1. Токены

| Токен | Формат | Срок |
| --- | --- | --- |
| Статический токен агента | `dsa_` + 43 символа base64url (32 случайных байта) | бессрочно или до `expiresAt` |
| OAuth access token | `dso_at_` + 43 символа | 1 час |
| OAuth refresh token | `dso_rt_` + 43 символа | 30 дней, **ротация** при каждом обновлении |
| Код авторизации | `dso_code_` + 43 символа | 5 минут, одноразовый |

В базе хранится только SHA-256 (hex) токенов и секретов. Токен передаётся только в заголовке `Authorization: Bearer …` (не в URL).

Области (scopes): `notes:read`, `notes:write` (`read_write` = обе).

### 2.2. OAuth 2.1 (по спецификации MCP 2026-07-28)

- Издатель (`issuer`) = публичный origin сервера (`publicUrl`). Ресурсы: `<publicUrl>/mcp` (канонический, указывается в метаданных) и `<publicUrl>/v1/agent`.
- Регистрация клиента: **Client ID Metadata Documents** (client_id — HTTPS-URL документа; сервер скачивает его: только HTTPS, только публичные адреса, ≤ 64 КиБ, 5 с, кэш 24 ч) и **динамическая регистрация** RFC 7591 (оставлена для совместимости). Клиенты CIMD — только публичные (`token_endpoint_auth_method: none`).
- Адреса возврата: `https://…`, `http://localhost|127.0.0.1|[::1]` (любой порт, RFC 8252) и собственные схемы приложений. Точное совпадение с зарегистрированными.
- Только `response_type=code` + **PKCE S256** (обязательно). Параметр `resource` (RFC 8707) проверяется; если клиент его не прислал — подставляется `<publicUrl>/mcp`.
- Ответ авторизации содержит `iss` (RFC 9207), в метаданных `authorization_response_iss_parameter_supported: true`.
- Ошибки до проверки `redirect_uri` показываются страницей, а не перенаправлением (защита от открытого редиректа).
- Экран согласия — серверная HTML-страница «Тихая бумага» (светлая/тёмная тема, без JS и внешних ресурсов, CSP `frame-ancestors 'none'`): выбор блокнотов (только «для агентов») и прав. Состояние запроса переносится в подписанном HMAC поле формы (15 минут), пользователь должен совпадать.
- Если пользователь не вошёл — перенаправление на `context.users.loginUrl(returnTo)`; если его нет — страница «Сначала войдите».
- Повторная авторизация того же клиента обновляет его разрешение (одно подключение на клиента), а не создаёт новое.
- Ответ `401` на `/mcp`: `WWW-Authenticate: Bearer resource_metadata="<publicUrl>/.well-known/oauth-protected-resource/mcp", scope="notes:read notes:write"` (+ `error="invalid_token"`, если токен был).
- Агент с правом `read` по OAuth, вызывающий пишущий инструмент, получает `403` с `error="insufficient_scope", scope="notes:read notes:write"` — клиент может запросить расширение прав (step-up). Для статических токенов — ошибка инструмента `forbidden`.

## 3. Инструменты MCP и REST

Входные схемы — `packages/agents/src/service/schemas.ts` (zod; из них SDK строит JSON Schema). Все идентификаторы — UUID.

| MCP-инструмент | REST | Права | Что делает |
| --- | --- | --- | --- |
| `list_spaces` | `GET /v1/agent/spaces` | read | Пространства с доступными блокнотами |
| `list_notebooks` | `GET /v1/agent/notebooks` | read | Блокноты, папки (с путём), число заметок, права |
| `list_notes` | `GET /v1/agent/notebooks/:notebookId/notes?folderId&limit&offset` | read | Заметки блокнота/папки, новые сверху |
| `search_notes` | `GET /v1/agent/search?query&notebookId&tag&limit` | read | Поиск: все слова, без учёта регистра; заголовок и теги весят больше; фрагмент текста |
| `read_note` | `GET /v1/agent/notes/:noteId` | read | Markdown + рукопись + комментарии (раздел 4) |
| `get_handwriting_image` | `GET /v1/agent/notes/:noteId/handwriting/:id.png?scale` | read | PNG рукописного фрагмента |
| `get_backlinks` | `GET /v1/agent/notes/:noteId/backlinks` | read | Кто ссылается (`noteLink`, `pageCard`) + исходящие ссылки |
| `list_tasks` | `GET /v1/agent/tasks?state&notebookId&scheduledFrom&scheduledTo&deadlineBefore&limit` | read | Задачи (`taskItem`) из всех доступных заметок |
| `create_note` | `POST /v1/agent/notes` | read_write | Новая заметка из Markdown (+ папка) |
| `edit_note` | `POST /v1/agent/notes/:noteId/edit` | read_write | Операции над блоками (раздел 5) |
| `add_comment` | `POST /v1/agent/notes/:noteId/comments` | read_write | Комментарий к блоку, можно привязать к цитате |
| `update_task` | `PATCH /v1/agent/tasks/:taskId` | read_write | Состояние, дата, дедлайн задачи |

MCP возвращает JSON в текстовом блоке (кроме `read_note` — Markdown + картинки, и `get_handwriting_image` — описание + картинка). Ошибка инструмента — `isError: true`, текст `<code>: <сообщение>`. REST-ошибки — формат `api.md`: `{ "error": { "code", "message" } }`, коды `bad_request`, `unauthorized`, `forbidden`, `not_found`, `conflict`, `rate_limited` (+ `Retry-After`), `payload_too_large`, `internal`. Сообщения написаны для модели: что не так и что сделать.

## 4. Markdown для агента (`read_note`)

- Заголовок заметки — отдельно (в MCP — первой строкой `# Заголовок` и строкой метаданных), тело — Markdown.
- После каждого блока — маркер `<!-- block:<blockId> -->`; у пунктов списка — в конце строки; у задач — `<!-- block:<blockId> task:<taskId> -->`.
- Задачи: `- [ ]` / `- [x]` / `- [-]` (отменена), `⏳ YYYY-MM-DD` — запланировано, `📅 YYYY-MM-DD` — дедлайн (как в Obsidian Tasks и в общем экспорте `@datascratch/shared`).
- Выноски — `> [!note|info|success|warning|danger] эмодзи`. Названия выносок Obsidian/GitHub при записи сводятся к ближайшему тону схемы: `tip`, `hint`, `check`, `done` → `success`; `important`, `abstract`, `summary`, `todo`, `question` → `info`; `caution`, `attention` → `warning`; `error`, `failure`, `bug` → `danger`; `example`, `quote` и неизвестные → `note` (так и сказано в описании инструментов); формулы — `$$…$$`; Mermaid — блок кода `mermaid`; ссылки на заметки — `[[Заголовок]]`; теги — `#тег`; маркер текста — `==…==`; подчёркивание — `<u>…</u>`; картинки и файлы — `attachment:<id>`; вложенный документ — `📄 [[Заголовок]] <!-- block:… note:<noteId> -->`.
- **Рукопись (D-11):** после блока, к которому она привязана, — `![✍️ <описание>](handwriting:<id>)`. Описание по-русски по `hint` штриха и тексту под ним, расширенному до целых слов: «подчёркнуто от руки: «…»», «зачёркнуто от руки», «обведено от руки», «выделено маркером», «стрелка от руки у», «заштриховано от руки», «пометка от руки у»; для штрихов-якорей блока — «заметка от руки на полях: «…»», «рисунок от руки», «пометки от руки на картинке «…»». В MCP к ответу прикладываются PNG (до 6 штук), в REST — `imageUrl`.
- Группа рукописи: штрихи одного текстового блока, чьи отмеченные участки ближе 24 символов, — одна картинка. `handwritingId` = id первого (самого раннего) штриха группы; принимается и id любого штриха группы.
- Штрихи, у которых удалены все якоря, не показываются (D-35).

Агент пишет Markdown в том же диалекте (`create_note`, `insert`, `replace`): `[[Заголовок]]` превращается в `noteLink`, если заметка с таким заголовком доступна агенту (иначе остаётся текстом), `[текст](note:<noteId>)` — тоже `noteLink`.

**Экранирование и дословное содержимое** (чтобы `read_note` → правка → `read_note` давали тот же текст):

- Символ, экранированный обратной косой (`\#`, `\*`, `\_`, `` \` ``, `\[`, `\=\=`…), — обычный текст: `\#не тег` не становится тегом. `read_note` экранирует так же всё, что иначе стало бы разметкой (`*`, `` ` ``, `[`, `]`, `<`, `\`, `_` на границе слова, `##`/`==`/`~~`/`$$`, `#` перед словом, `>`/`#`/`-`/`+`/`1.` в начале строки).
- Формулы `$$…$$` (в одну или несколько строк, в том числе внутри цитаты) и код (`` `…` ``, блоки ```` ``` ````) берутся из исходника **дословно** — обратные косые в LaTeX не теряются.
- Перевод строки внутри абзаца сохраняется как разрыв строки (`hardBreak`); `read_note` пишет его как `\` + перевод строки, внутри цитат и пунктов списка — с префиксом `> ` или отступом.
- Пустой абзац в конце вставки отбрасывается.

## 5. Правки агента (D-10)

Операции `edit_note` (по порядку, **атомарно**: при ошибке любой операции не меняется ничего):

| `op` | Поля | Смысл |
| --- | --- | --- |
| `insert` | `position`, `markdown` | Вставить блоки; `position` = `{after: blockId}` \| `{before: blockId}` \| `{at: "start"\|"end"}` (start — сразу после заголовка) |
| `replace` | `blockId`, `markdown` | Заменить блок; первый новый блок **сохраняет `blockId`** (комментарии и заметки на полях остаются на месте) |
| `delete` | `blockId` | Удалить блок (опустевший список удаляется) |
| `move` | `blockId`, `position` | Переместить блок |
| `replace_text` | `blockId`, `find`, `replace`, `occurrence?` | Заменить фрагмент текста внутри блока; `find: ""` — дописать в конец |

- Пункты списка вставляются в список, строки — в таблицу; прочие блоки рядом с пунктом списка «выходят» из списка.
- Заголовок заметки нельзя удалить/заменить/переместить, переименование — `replace_text` в блоке `title`; плагин синхронизирует `NoteMeta.title`, `tags`, `updatedAt` в индексе блокнота.
- **Сохранность рукописи:** `replace_text` меняет только различающуюся середину (общие начало и конец остаются теми же элементами Yjs), поэтому якоря штрихов на нетронутых символах живы. При `move` Yjs не умеет переносить элемент: блок копируется, а у затронутых штрихов переписываются `anchors` (поле изменяемое, `strokes.md` §1) — на те же символы копии; якоря комментариев — тоже.
- Весь вставленный агентом в **существующую** заметку текст получает метку `agentEdit { agentId: <grantId>, at }` (подсветка, `document-model.md`). Метки пишутся объектом атрибутов (`{ bold: {} }`), `null`-атрибуты узлов не записываются (`document-model.md` §4.1); при вставке текста всегда передаётся явный набор меток.
- Правка = обычное обновление Yjs: плагин меняет копию документа и передаёт серверу только разницу (`context.data.applyUpdate` с `origin: { kind: "agent", grantId, userId, agentName, action }`); сервер шифрует, присваивает `seq`, хранит в истории версий и рассылает клиентам. Откат — через историю версий.
- Новая заметка: `context.data.createNoteDoc` (сервер создаёт ключ заметки и возвращает его обёртку ключом блокнота) → содержимое **без** меток `agentEdit` → `NoteMeta` в индексе блокнота с `createdByAgent: { agentId: <grantId>, agentName, at }` (D-45).

## 6. Рендер рукописи в PNG

- `@napi-rs/canvas`, шрифты в комплекте (Inter для текста, Newsreader для заголовков) — картинка одинакова на любой машине.
- Текст блока раскладывается упрощённо: колонка 600 pt, перенос по словам, размеры по `design-tokens.md` (title 34, h1 28, h2 22, h3 19, body 17), межстрочный 1.5 (заголовки 1.25), метки bold/italic/подчёркивание/зачёркивание/маркер/ссылка.
- Штрихи — по `strokes.md`: точка = начало глифа якоря + (x, y) × размер шрифта; разрыв на смене строки; точки с удалёнными якорями пропускаются, сегменты короче 2 точек не рисуются; толщина `width × f(pressure) × (fontSize/17)` (блоки — `× blockWidth/600`), наклон для `pencil`/`marker`; маркер под текстом с `multiply`.
- Кадр: отмеченные строки ± 1 строка контекста (контекст бледнее) + всё, куда заходят штрихи. Масштаб по умолчанию 2 px/pt, ширина 1280 px.
- Заметка на полях — весь блок; рисунок — `height` блока; картинка — исходное изображение (если `context.data.loadAttachmentImage` есть) или заглушка.
- Кэш в памяти процесса: ключ (пользователь, заметка, `seq`, группа, масштаб), 200 картинок.

## 7. Журнал и лимиты

- Каждый вызов инструмента / REST-операции пишется в журнал (`AuditEntry`: grant, пользователь, время, `mcp`/`rest`, действие, блокнот, заметка, успех, код ошибки, длительность) — и успешные, и неудачные. Ошибка записи журнала не роняет операцию.
- Лимиты в памяти процесса (D-25): на разрешение — 120 запросов/мин, всплеск 60; на `/oauth/register` и `/oauth/token` — 30/мин с одного IP. Превышение — `429` + `Retry-After`.

## 8. `/v1/agent-tokens` (уточнение `api.md`)

Реализуются плагином (авторизация — пользователь через `context.users.authenticate`):

| Метод | Путь | Тело → ответ |
| --- | --- | --- |
| POST | `/agent-tokens` | `{ name, notebookIds, permission, expiresAt? }` → `201 { id, kind, name, clientId, notebookIds, permission, createdAt, expiresAt, lastUsedAt, token }`; блокноты обязаны быть «для агентов», иначе `400` |
| GET | `/agent-tokens` | `AgentToken[]` (`api.md`) + поля `kind` (`static`/`oauth`) и `clientId` — список активных разрешений **обоих видов** (статические и OAuth-подключения), без секретов |
| DELETE | `/agent-tokens/:id` | отзыв (и OAuth-подключений) → `204` |
| GET | `/agent-tokens/:id/audit?limit&before` | журнал, новые сверху |

## 9. Контекст плагина (интерфейс с сервером)

Типы — `packages/agents/src/context.ts`. Сервер реализует:

Последний необязательный параметр `grantId` у методов `data` передаётся при каждом вызове от имени агента: сервер выполняет запрос под ролью с Row-Level Security, ограниченной блокнотами разрешения (D-30). Без него (экран согласия, `/v1/agent-tokens`) — только блокноты «для агентов» пользователя.

- `data.listAgentNotebooks(userId)` — блокноты «для агентов» `{ id, name, icon, space, createdAt }`;
- `data.loadDoc(userId, docId)` → `{ doc: Y.Doc (расшифрованный), seq }` или `null` — только для документов блокнотов «для агентов» (расшифровка ключом из KMS, R-10);
- `data.docSeqs?(userId, docIds)` — текущие `seq` без расшифровки (для кэша поиска);
- `data.applyUpdate(userId, docId, update, origin)` → `{ seq }`;
- `data.createNoteDoc(userId, notebookId, noteId)` → `{ wrappedKey }`;
- `data.loadAttachmentImage?(userId, attachmentId)`;
- `users.authenticate(request)` — Bearer пользователя или сессия браузера (для экрана согласия нужна cookie-сессия веба); `users.loginUrl?(returnTo)`;
- `store.listAudit(grantId, { limit, before })` — `before` = ISO-время, записи с `at` строго раньше, новые сверху;
- `store` — хранение разрешений, OAuth-клиентов, кодов, токенов и журнала (таблицы PostgreSQL на стороне сервера; in-memory версия — `@datascratch/agents/testing`).

## 10. Решённые вопросы стыков

1. **Имена блокнотов и пространств** (решение координатора 2026-10-25): клиенты дублируют `name`, `icon`, `space: { id, name, icon }` (предложено добавить и `color` — токен цвета блокнота) в `meta` документа `notebook` (при создании, переименовании и включении режима «для агентов»), см. `document-model.md`. Плагин берёт значения из `AgentNotebook`, если сервер их знает, иначе из `meta` документа блокнота; имени нет — «Без названия». Это касается и экрана согласия OAuth: там рядом с именем — иконка блокнота (эмодзи или встроенный SVG вместо символа SF, например `globe`) на плашке его цвета (`meta.color`, иначе акцентного).
