# Модель данных — ЧЕРНОВИК

> Статус: ПРЕДЛОЖЕНО. Будет уточняться на этапе 1 (формат штриха) и этапах 2–3 (документ, метаданные, сервер). Здесь — общий каркас, чтобы все части проекта говорили на одном языке.

## Иерархия организации

```
Аккаунт
└── Пространство (Личное, Работа, Учёба…)
    └── Блокнот  ← здесь задаётся режим шифрования (приватный / для агентов)
        └── Папка (вложенность без ограничений)
            └── Заметка
```

Соотношение «пространство / блокнот / папка» — ОТКРЫТО (`open-questions.md`). Теги, умные теги, избранное — поперёк иерархии.

## Заметка

| Часть | Где хранится | Формат |
| --- | --- | --- |
| Текст (дерево блоков) | CRDT-документ Yjs/Yrs | Бинарные обновления Yjs |
| Слой рукописи | Тот же CRDT-документ (отдельная коллекция внутри) | Штрихи с якорями (см. ниже) |
| Вложения | Отдельные файлы (диск/S3) | Зашифрованные куски с докачкой |
| Метаданные | Отдельная запись | Заголовок, теги, ссылки, даты, пространство, папка |

Хранить штрихи **в том же CRDT-документе**, что и текст, — ПРЕДЛОЖЕНО: тогда текст и пометки синхронизируются и откатываются атомарно. Проверяется на этапе 1.

## Штрих (черновик для прототипа)

```
Stroke {
  formatVersion: Int        // с первого дня, см. risks.md R-03
  id: UUID
  tool: pen | marker | pencil | eraser…
  color, width
  anchor: Anchor            // к чему привязан штрих целиком
  points: [StrokePoint]
  createdAt, author         // author: пользователь / гость / агент
}

StrokePoint {
  charAnchor: RelativePosition  // относительная позиция CRDT на символ
  dx, dy: Float                 // смещение от глифа в единицах размера шрифта
  pressure, altitude, azimuth   // нажим и наклон
  roll?: Float                  // вращение (Pencil Pro), если есть
  t: Float                      // время от начала штриха
}

Anchor =
  | textRange(start: RelativePosition, end: RelativePosition)  // пометки на тексте
  | paragraph(blockId)                                         // заметки на полях
  | drawingBlock(blockId)                                      // блок рисования
  | image(attachmentId)                                        // рисование на картинке
```

Для якорей `paragraph`, `drawingBlock`, `image` точки хранятся в локальных координатах блока/картинки (нормированных), а не через `charAnchor`.

Хранить якорь на **каждую** точку может оказаться избыточным; альтернатива — якорь на сегмент между переносами. Выбор — по результатам прототипа.

## Сервер (PostgreSQL) — реализовано (поток server, 2026-10-25)

Схема — `apps/server/src/db/schema.ts`, миграции — `apps/server/drizzle/`. Содержимое пользователя сервер хранит только зашифрованным (`bytea`); пространства, папки и метаданные заметок живут внутри зашифрованных документов `account` и `notebook` (`contracts/document-model.md`), отдельных таблиц для них нет.

| Таблица | Что хранит |
| --- | --- |
| `users` | email, соль и параметры KDF, `Argon2id(loginKey)`, `Argon2id(recoveryLoginKey)`, обёрнутый masterKey (паролем и ключом восстановления), `accountDocId` |
| `devices` | устройства = сессии (имя, последний вход, отзыв) |
| `refresh_tokens` | SHA-256 refresh-токенов, срок, отметка использования (ротация) |
| `security_events` | журнал безопасности: смена пароля, восстановление, замена ключа восстановления (устройство, время) |
| `recovery_tokens` | одноразовые токены восстановления (15 мин) |
| `notebooks` | режим `private`/`agent`, notebookKey под masterKey; в режиме «для агентов» — ещё под ключом сервера `DS_KMS_KEY` |
| `docs` | документы `account`/`notebook`/`note`: владелец, блокнот, `last_seq`, `snapshot_seq`, счётчики с последнего снимка |
| `doc_updates` | зашифрованные обновления Yjs: `(doc_id, seq)`, устройство, `client_msg_id` |
| `doc_snapshots` | зашифрованные снимки `(doc_id, seq = baseSeq)` — они же версии истории |
| `attachments`, `attachment_chunks` | метаданные вложений и загруженных кусков; сами куски — в хранилище файлов (`att/<id>/<index>`) |
| `storage_trash` | ключи файлов к удалению (заполняет триггер при удалении кусков) |
| `shares` | ссылки шеринга: цель (заметка/блокнот), право, срок, отзыв |
| `agent_grants` | разрешения агентам: статический токен или OAuth-подключение (SHA-256 секрета, блокноты, право, срок, отзыв) |
| `oauth_clients`, `oauth_codes`, `oauth_tokens` | OAuth 2.1 для MCP (клиенты, одноразовые коды, токены — SHA-256) |
| `agent_audit` | журнал действий агентов (через MCP/REST, успех, длительность) |
| схема `pgboss` | служебные таблицы очереди задач |

Удаление каскадное: аккаунт → всё; блокнот → его документы; документ → обновления, снимки, вложения. Файлы вложений удаляет фоновая задача по `storage_trash`.

**Row-Level Security (D-30):** роль `ds_agent` (без входа) с политиками на `notebooks`, `docs`, `doc_updates`, `doc_snapshots`, `attachments`, `attachment_chunks`. Запросы агента выполняются под этой ролью с `ds.agent_user_id` и `ds.agent_grant_id` в настройках транзакции; видны только блокноты пользователя в режиме «для агентов» (с грантом — только блокноты гранта), запись — только при праве `read_write`. К остальным таблицам у роли доступа нет.
