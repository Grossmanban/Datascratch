# Технологический стек — РЕШЕНО (2026-10-25)

Утверждён пользователем 2026-10-25 (D-21, D-22) с поправками D-25, D-26, D-27. Обоснования и рассмотренные альтернативы — в соответствующих ADR в `docs/decisions/`.

**Главный принцип:** раз весь код пишет Claude — как можно меньше языков и только проверенные библиотеки. В проекте **два языка: Swift и TypeScript**.

## iPhone / iPad (`apps/ios`)

| Что | Чем | Почему коротко |
| --- | --- | --- |
| Язык | Swift 6 | Нативная платформа |
| Оболочка (навигация, списки, настройки, сайдбар) | SwiftUI | Быстро и красиво для стандартных экранов |
| Редактор | UIKit + **TextKit 2** | Единственный способ привязать штрихи к глифам текста; WebView даёт задержку пера |
| Слой пера | Свой рендер: Metal или Core Animation — выбрать на прототипе | `PKCanvasView` не умеет привязку к тексту |
| Локальная база | SQLite через **GRDB** | Надёжно, быстро, офлайн |
| CRDT | **Yrs** (Rust-версия Yjs) со Swift-обёрткой | Бинарно совместим с Yjs в вебе и на сервере; проверяется уже на прототипе (D-27), запасной вариант — Automerge |
| Криптография | **libsodium** (swift-sodium) | Та же библиотека, что в вебе и на сервере |

## Веб (`apps/web`)

| Что | Чем | Почему коротко |
| --- | --- | --- |
| Сборка и фреймворк | **Vite + React + TypeScript**, PWA | Офлайн-первое клиентское приложение; Next.js/Nuxt не нужны — SSR бесполезен, сервер не видит содержимого |
| Редактор | **TipTap (ProseMirror) + Yjs** | Самая проверенная связка для совместного редактирования |
| Слой пера | Canvas + Pointer Events с нажимом | Работает со стилусами и в Safari на iPad |
| Офлайн-хранилище | IndexedDB через **Dexie** | Стандарт для браузера |
| UI | Своя дизайн-система на **Radix + Tailwind + Motion** | Доступные примитивы + полная свобода дизайна |
| Лендинг (позже, отдельно) | Astro | Статический сайт |

## Сервер (`apps/server`)

| Что | Чем | Почему коротко |
| --- | --- | --- |
| Язык и платформа | **TypeScript на Node.js** | Родная среда Yjs, общие типы с вебом, официальный MCP SDK |
| Фреймворк | **Fastify** | Быстрый, зрелый, хорошая типизация |
| База данных | **PostgreSQL** (D-30) | Надёжность, Row-Level Security, транзакционные миграции, очередь задач без Redis |
| Работа с БД | **Drizzle** | Типобезопасно, легко |
| Очередь фоновых задач | **pg-boss** (на PostgreSQL) | Рендер PNG и т. п. без Redis |
| Хранение файлов | Папка на диске по умолчанию / внешнее S3 по настройке (D-26) | Ноль лишних сервисов |
| Реальное время | WebSocket, рассылка внутри процесса (D-25) | Redis не нужен при одном процессе |
| MCP | Официальный TypeScript SDK, Streamable HTTP, OAuth 2.1 | Стандарт |

**Не используем:** Redis (D-25), MinIO (D-26), Next.js/Nuxt, собственное ядро на Rust (D-22).

## Совместимость iOS ↔ веб без общего ядра (D-22)

Общий бинарный формат Yjs/Yrs + libsodium с обеих сторон + **общие тестовые векторы** (`packages/test-vectors`), которые прогоняются и в Swift, и в TypeScript.

## Ресурсы сервера

В простое ~300–400 МБ памяти (Node.js ~150 МБ, PostgreSQL ~150–200 МБ). Процессор почти не нагружен: в приватных блокнотах сервер только хранит и пересылает шифр. Всплески — запросы агентов, рендер PNG, первая синхронизация нового устройства.

## Как будем масштабироваться, если понадобится

Только при платном хостинге для многих пользователей (D-18): несколько копий сервера + рассылка правок между ними через PostgreSQL LISTEN/NOTIFY, при очень большой нагрузке — Redis или его свободный аналог Valkey. Рассылка спрятана за интерфейсом, замена затрагивает только её.
