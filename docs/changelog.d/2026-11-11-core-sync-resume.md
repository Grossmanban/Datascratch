- **Синхронизация, протокол 3 — возобновление по курсору аккаунта** (`sync-protocol.md` §3.1, поправка к D-31): при переподключении клиент шлёт `resume { cursor }`, а не `subscribe` всей библиотеки. Сервер отвечает `resumed`: документы, изменённые после курсора (с последним `seq`), удалённые или ставшие недоступными, и новый курсор. Он же включает подписку на все документы аккаунта. Клиент подписывает только отставшие документы. Неизвестный или старый курсор — `reset`, полная подписка, как в версии 1. Курсор сохраняется, только когда клиент догнал всё подписанное; документы, не «покрытые» курсором, подписываются всегда. `SYNC_PROTOCOL_LATEST = 3`. В `@datascratch/shared`: `SyncClient`, `MemorySyncHub` (`grantDoc`, `deleteDoc`), `SyncStorage.getResumeState` / `setResumeState`, векторы `sync/resume.json`; сервер и iOS — следом.
