# D-25. Redis не используем

- **Статус:** РЕШЕНО (пользователь, 2026-10-25)
- **Дата:** 2026-10-25
- **Связано:** D-12, D-21, D-30, `docs/spec/06-data-server.md`

## Контекст

В предложенном стеке Redis был для реального времени. Пользователь спросил, зачем он нужен. Redis обычно нужен, когда работает **несколько копий сервера** — им нужна общая «доска объявлений» для пересылки правок; попутно — лимиты, сессии, кэш, очереди.

## Решение

Redis убираем. Сервер работает одним процессом (для одного пользователя и узкого круга — с огромным запасом):

| Задача | Без Redis |
| --- | --- |
| Рассылка правок между устройствами | В памяти процесса |
| Лимиты запросов агентов | Счётчики в памяти процесса |
| Сессии, токены | PostgreSQL |
| Очередь рендера PNG | PostgreSQL (pg-boss) |

Рассылка правок спрятана за отдельным интерфейсом.

## Будущее

Redis понадобится, только если появится платный хостинг (D-18) с несколькими копиями сервера и многими тысячами одновременных подключений. Даже тогда сначала хватит PostgreSQL LISTEN/NOTIFY. Если до Redis дойдёт — рассмотреть и Valkey (свободный аналог после смены лицензии Redis).

## Последствия

Минус один сервис, ~20+ МБ памяти и одна точка отказа; установка проще.
