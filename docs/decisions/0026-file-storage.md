# D-26. Хранение файлов: диск по умолчанию, внешнее S3 — опционально; без MinIO

- **Статус:** РЕШЕНО (пользователь, 2026-10-25)
- **Дата:** 2026-10-25
- **Связано:** D-18, D-21, `docs/spec/06-data-server.md`

## Контекст

Вложения (картинки, PDF, файлы) хранятся отдельно от базы — удобнее отдавать по частям и докачивать, база не раздувается. В предложенном стеке для self-hosting был MinIO (своё S3-совместимое хранилище). По имеющимся сведениям, бесплатная версия MinIO в 2025 году ушла в режим поддержки (готовые сборки перестали публиковаться) — строить на ней нежелательно.

## Решение

Хранение файлов — за интерфейсом с двумя реализациями, выбор одной строкой в настройках:
- **папка на диске сервера** — по умолчанию (для автора на старте и для self-hosting);
- **внешнее S3-совместимое хранилище** (Hetzner Object Storage, Cloudflare R2, Backblaze B2 и т. п.) — когда вложений станет много.

Файлы шифруются на устройстве, поэтому внешнее хранилище видит только шифр (для блокнотов «для агентов» — тоже шифр, ключ на нашем сервере).

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| MinIO | S3 у себя | Лишний сервис, ~200 МБ памяти, неясное будущее проекта |
| Garage / SeaweedFS | S3 у себя, живые проекты | Лишний сервис без нужды на нашем масштабе |
| Файлы в PostgreSQL | Всё в одном месте | Раздувает базу и бэкапы, плохо для больших файлов |
| **Диск + опционально внешнее S3** | Ноль лишних сервисов, масштабируется переключением | Резервное копирование должно включать папку с файлами |

## Последствия

Сервер = Node.js + PostgreSQL + папка с файлами. Два контейнера вместо четырёх (вместе с D-25), ~300–400 МБ памяти.
