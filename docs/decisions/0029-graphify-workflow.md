# D-29. Graphify: порядок работы, чтобы граф был всегда актуален

- **Статус:** РЕШЕНО (требование пользователя: граф — главный и всегда актуальный); технические детали — ПРЕДЛОЖЕНО
- **Дата:** 2026-10-25
- **Связано:** D-23, `CLAUDE.md`, `docs/development.md`

## Контекст

Пользователь: Graphify должен быть самым главным и всегда самым актуальным; любой ИИ, впервые видящий репозиторий, должен понять всё идеально.

Как устроен Graphify (версия 0.9.95, пакет `graphifyy`):
- граф состоит из **структурного слоя** (код, файлы и заголовки документов — строится локально, без ИИ) и **смыслового слоя** (понятия, решения и связи из документов — требует прохода языковой моделью);
- изменения кода обновляются командой `graphify update .` — без ИИ и бесплатно;
- изменения документов обновляются командой `/graphify . --update` в сессии Claude Code — оба слоя по изменённым файлам (ИИ сессии сам выступает моделью, ключи API не нужны);
- git-хук (`graphify hook install`) после коммита пересобирает граф **только по изменённому коду**, документы пропускает целиком (если графа ещё нет, хук строит структурный слой всего проекта);
- граф лежит в `graphify-out/` (`graph.json`, `GRAPH_REPORT.md`, `graph.html`).

## Решение

1. **Иерархия:** `docs/` — источник истины; граф — главный инструмент навигации поверх `docs/` и кода. При расхождении прав `docs/`, граф пересобирается.
2. **Граф хранится в репозитории** (`graphify-out/` коммитится), чтобы новый ИИ получал карту сразу, без сборки. Не коммитятся только машинно-зависимые файлы (пути интерпретатора и корня).
3. **Обновление графа — часть «готово»** для любого коммита (`CLAUDE.md`): код → `graphify update .`; документы → инкрементальное обновление скриптом `tools/graphify_docs.py` (`prepare` → смысловой проход агентами → `finish`; по сути `/graphify . --update`, оформленный так, чтобы шаги не терялись и проверка «не пропали ли узлы неизменённых файлов» выполнялась всегда). Граф коммитится вместе с изменениями.
4. **git-хук** пересобирает граф по изменённому коду после каждого коммита.
5. **Стартовый хук Claude Code** (`.claude/hooks/session-start.sh`) в каждой сессии ставит Graphify, если его нет, ставит git-хук и предупреждает, если граф отстал от документов.
6. **`docs/history/` исключена из графа** (`.graphifyignore`), чтобы граф показывал только актуальное состояние, а не устаревшие формулировки из архива. Также исключены служебные файлы `.claude/`.

## Последствия

Каждый коммит с документацией требует семантического прохода (токены сессии). Graphify — молодой сторонний инструмент (версия 0.x, часто меняется): если он сломается или исчезнет, проект не теряет знаний — всё в `docs/`, граф можно пересобрать или заменить (R-09).
