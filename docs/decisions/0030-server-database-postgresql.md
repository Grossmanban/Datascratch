# D-30. База данных сервера — PostgreSQL

- **Статус:** РЕШЕНО (подтверждено пользователем 2026-10-25)
- **Дата:** 2026-10-25
- **Связано:** D-18, D-21, D-25, `docs/spec/06-data-server.md`

## Контекст

На устройствах базы заданы платформой (iOS — SQLite, веб — IndexedDB). Выбор нужен только для сервера. Сервер хранит: аккаунты, блокноты, права, ссылки шеринга, токены агентов; зашифрованные обновления и снимки истории; журнал агентов. Это обычные связанные таблицы и много небольших зашифрованных записей.

## Решение

PostgreSQL.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| **PostgreSQL** | Стандарт надёжности; одновременная запись с разных устройств и от агентов; Row-Level Security; транзакционные изменения схемы; очередь задач (pg-boss) и LISTEN/NOTIFY вместо Redis; зрелые бэкапы с откатом на любую минуту; свободная лицензия; подходит и для одного, и для многих пользователей | Отдельный сервис, ~150–200 МБ памяти |
| SQLite на сервере | Проще всего: один файл, нет сервиса | Одна пишущая операция за раз; при платном хостинге пришлось бы переезжать |
| MySQL | Надёжная, массово используется | Нет Row-Level Security; изменения схемы не транзакционные (прерванное обновление может оставить «полуобновлённую» базу); библиотеки очередей и LISTEN/NOTIFY — только для PostgreSQL; принадлежит Oracle. По памяти и скорости на нашем масштабе — паритет |
| MongoDB | Гибкие документы без схемы | Данные связанные; больше памяти; слабее гарантии целостности |

Вопрос «почему не MySQL» задан пользователем отдельно; особой привязки к MySQL у него нет (сервер администрировать знакомым инструментом было бы весомым доводом — не тот случай).

## Последствия

Права токенов агентов дублируются на уровне базы (Row-Level Security) — ошибка в коде сервера не даёт агенту прочитать чужой блокнот. Миграции схемы безопасны для self-hosting-обновлений.
