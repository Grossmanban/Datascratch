# D-39. Разработка параллельными сессиями; Claude сам вливает в main

- **Статус:** РЕШЕНО (пользователь, 2026-10-25)
- **Дата:** 2026-10-25
- **Связано:** D-19, D-28, `docs/roadmap.md`, `docs/development.md`

## Контекст

Пользователь поручил сделать проект целиком, распределив работу на несколько сессий Claude Code. Mac будет доступен позже; платный аккаунт Apple Developer есть. Приоритет — всё равномерно (iOS, веб, сервер, агенты одновременно).

## Решение

- Работа делится на **потоки** с чёткими зонами владения (каталогами). Каждый поток — отдельная сессия Claude Code и отдельная ветка `claude/<поток>`.
- Потоки согласуются через **контракты** (`docs/architecture/contracts/`): формат документа, штрихов, протокол синхронизации, шифрование, API, дизайн-токены. Контракт меняется только через сессию-координатора.
- **Claude-координатор сам вливает** ветки в `main`, когда CI зелёный. Пользователь смотрит результат, когда удобно.
- Репозиторий остаётся **публичным**: сборка iOS на macOS-раннерах GitHub бесплатна и не ограничена — без Mac это единственная проверка iOS-кода.
- Строгое «сначала прототип пера, потом остальное» заменяется параллельной работой: сервер, веб и общие пакеты от пера не зависят. Риск пера (R-01) по-прежнему проверяется в первую очередь в потоке iOS-редактора; ощущение пера подтверждает пользователь на iPad, когда будет Mac.
- XcodeGen (D-28) принят в работу.
