# D-42. Yrs в iOS — собственная обёртка через UniFFI

- **Статус:** РЕШЕНО (технически — поток ios-core, утверждено координатором 2026-10-25; уточняет D-27 и D-31)
- **Дата:** 2026-10-25
- **Связано:** D-22, D-27, D-31, R-06, `apps/ios/Packages/DSCore`

## Контекст

Для iOS нужен Yrs (Rust-версия Yjs) со Swift-интерфейсом, способный работать с XML-деревом y-prosemirror, относительными позициями и отменой (контракты document-model, strokes). Это был главный технический риск стека (R-06).

## Решение

Готовая обёртка `y-crdt/yswift` не подошла: нет XML-типов (XmlFragment/XmlElement/XmlText), нет относительных позиций, старая версия yrs, проект заброшен. Сделана **собственная** обёртка через UniFFI поверх **yrs 0.25** (`apps/ios/Packages/DSCore/yrs-ffi`): крупнозернистый API (один документ, узлы по путям, пакетные операции в одной транзакции), относительные позиции с признаком «символ удалён», отмена, наблюдатели. xcframework собирается в CI и публикуется релизом.

yrs **вендорена с минимальным патчем** (`yrs-ffi/vendor/PATCHES.md`): при следовании redone терялось смещение внутри элемента, и якорь пометки после отмены удаления съезжал; поведение сверено с Yjs.

## Рассмотренные варианты

| Вариант | Итог |
| --- | --- |
| `y-crdt/yswift` | Не подходит: нет XML-типов и относительных позиций |
| Automerge (запасной вариант D-27) | Не понадобился |
| **Своя UniFFI-обёртка над yrs 0.25** | Выбрано; совместимость Yrs ↔ Yjs проверена в обе стороны на документе y-prosemirror и общими тестовыми векторами |

## Последствия

- Риск R-06 снят.
- В проекте появился небольшой Rust-крейт (обёртка) — это не «своё ядро» (D-22 в силе): логика остаётся в Swift и TS, Rust — только мост к готовой библиотеке.
- При обновлении yrs нужно переносить патч (или проверить, что он принят в апстрим).
