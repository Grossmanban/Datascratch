# D-44. Колонки на iPad: сайдбар управляется только своей кнопкой

- **Статус:** РЕШЕНО (пользователь, 2026-10-26); раскладка из трёх панелей заменена D-47 (не больше двух уровней), правило «сайдбар управляется своей кнопкой» действует
- **Дата:** 2026-10-26
- **Связано:** D-15, D-38, `docs/spec/05-organization-design.md`

## Контекст

В build 6–8 открытие документа на iPad прятало сайдбар, а закрытие одной панели могло спрятать другую; пользователь путался: «закрываешь одну панель — пропадает первая, её приходится отдельно вызывать, панели работают нелогично».

## Решение

Три панели: **Сайдбар | Список | Документ** (технически — сайдбар и рабочая область, которая сама раскладывает список и документ).

- Сайдбар показывает и прячет **только** его кнопка (и свайп от края). Ничто другое его не трогает; состояние запоминается.
- Открытие документа сайдбар не прячет (заменяет прежнее правило «сайдбар прячется при открытии документа»).
- «Закрыть документ» (×) убирает только документ: список (или задачи/календарь) занимает всю рабочую область, сайдбар остаётся как был.
- «На весь экран» — единственный режим, который прячет сайдбар и соседнюю панель; выход возвращает ровно прежнюю раскладку.
- Если рабочей области не хватает ширины (портрет с сайдбаром, < 640 pt), документ показывается один, список возвращается при закрытии документа — сайдбар не трогается.
- iPhone и узкое окно — стек экранов.

Поведение проверяется UI-тестами в портрете и альбоме.
