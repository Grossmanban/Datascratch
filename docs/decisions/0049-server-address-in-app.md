# D-49. Адрес сервера вводится в приложении, а не вшит в сборку

- **Статус:** РЕШЕНО (пользователь, 2026-10-26); несколько серверов одновременно — на будущее (этап 6)
- **Дата:** 2026-10-26
- **Связано:** D-13 (шеринг по ссылке), D-34 (вход), `docs/spec/06-data-server.md`, `docs/spec/08-sharing.md`, `docs/roadmap.md` (этап 6), заметка «Бэкап и переезд сервера — проект» (блокнот «Ии», папка «Datascratch dev»)

## Контекст

Адрес сервера iOS-приложения сейчас задаётся при сборке (`DS_SERVER_URL`). При переезде сервера на новый домен нужна новая сборка; человек со своим сервером (self-hosting) не может подключиться к нему из TestFlight-сборки. Пользователь: «нужно сделать, чтобы сервер не был зашит в сборку, а вводился вручную», и чтобы ссылка-приглашение сразу указывала, на каком сервере регистрироваться.

## Решение

1. **Сейчас (следующая задача iOS после D-48):** на экране входа и регистрации есть поле «Сервер» — по умолчанию подставлен наш сервер (значение из сборки остаётся только *подсказкой по умолчанию*). Можно ввести свой адрес; приложение проверяет его (`GET /v1/health`) до входа. Адрес хранится вместе с аккаунтом на устройстве. Сменить сервер = выйти и войти на другом (с предупреждением о неотправленных изменениях, как при обычном выходе). В настройках виден текущий сервер.
2. **Ссылки несут сервер (вместе с совместной работой):** ссылка на шеринг и приглашение содержит адрес сервера. Открыл ссылку → приложение (или веб) уже выбрало этот сервер → человек входит или регистрируется → сразу получает то, чем с ним поделились.
3. **Будущее (этап 6):** несколько серверов/аккаунтов одновременно — как несколько аккаунтов почты: переключатель аккаунтов, у каждого свой сервер, свои пространства и ключи.

Веб-версия по-прежнему работает с сервером своего домена (её отдаёт сам сервер); выбор сервера в вебе — вместе с пунктом 3.

## Нюансы

- Universal Links открывают приложение только для доменов, прописанных в сборке. Ссылка с чужого сервера откроется в браузере; из веба — кнопка «Открыть в приложении» (собственная схема `datascratch://` с адресом сервера).
- Проверка адреса: только `https://` (кроме `localhost` для разработки); показ имени сервера и версии из `/v1/health` до ввода пароля.
- Сервер узнаёт только то, что человек к нему подключился; ключи и пароль по-прежнему не уходят.

## Рассмотренные варианты

| Вариант | Итог |
| --- | --- |
| **Поле «Сервер» при входе, по умолчанию наш** | Выбрано |
| Адрес в сборке (как сейчас) | Отклонено: новая сборка при каждом переезде, нет self-hosting |
| Скрытая настройка | Отклонено: нужно и для приглашений, и для чужих серверов |
