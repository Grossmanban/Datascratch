# D-50. Лицензия кода — AGPL-3.0 на весь проект

- **Статус:** РЕШЕНО (пользователь, 2026-10-26)
- **Дата:** 2026-10-26
- **Связано:** D-18 (монетизация), D-24 (название), заметка «Стратегия продукта — черновик» (блокнот «Ии», папка «Datascratch dev»)

## Контекст

Репозиторий открыт, но лицензии не было — по закону это «все права защищены»: другим нельзя законно ставить и использовать программу. Пользователь хочет свободный софт, который любая команда может развернуть на своём сервере, и оставить себе путь к заработку («открытое ядро»).

## Решение

- Весь репозиторий — **GNU AGPL-3.0-only** (`LICENSE`): сервер, веб, iOS/iPadOS, общие библиотеки. В `package.json` — `"license": "AGPL-3.0-only"`.
- Все права на код — у владельца проекта. Сторонние участники подписывают **CLA** (передают права на свой вклад), чтобы владелец мог публиковать приложение в App Store и при желании выпускать платные версии (`CONTRIBUTING.md`).
- App Store: конфликт GPL с правилами Apple возникает только для чужого GPL-кода; владелец публикует своё приложение сам (как Signal). Копиям проекта своё приложение не нужно — наше подключается к любому серверу (D-49).
- Заработок — без ограничений сверх лицензии: поддержка, установка, облачный хостинг, платные дополнения своим кодом, товарный знак на финальное название (D-24).

## Рассмотренные варианты

| Вариант | Итог |
| --- | --- |
| **AGPL-3.0 на всё** | Выбрано: одна лицензия; облачные копии обязаны открывать изменения |
| AGPL сервер + Apache-2.0 клиенты | Отклонено: клиенты можно было бы закрыть и продавать |
| MIT / Apache на всё | Отклонено: любой может сделать закрытую платную версию |
| BSL / FSL («исходники видны») | Отклонено: это не свободный софт |

## Что ещё сделать

- Проверить лицензии всех зависимостей на совместимость с AGPL (ожидаемо MIT/BSD/ISC/Apache — совместимы).
- Перед коммерческим запуском показать выбор юристу (это не юридическая консультация).
