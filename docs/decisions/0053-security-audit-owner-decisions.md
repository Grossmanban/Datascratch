# D-53. Решения владельца по аудиту безопасности 2026-10-27

- **Статус:** РЕШЕНО (пользователь, 2026-10-27)
- **Дата:** 2026-10-27
- **Связано:** `docs/spec/06-data-server.md` («Квоты и регистрация», вход и устройства), `docs/spec/07-encryption.md` (отключённое устройство), `docs/architecture/contracts/api.md`, `docs/architecture/contracts/sync-protocol.md`

## Контекст

Аудит безопасности 2026-10-27 нашёл места, где поведение должен выбрать владелец, а не код:

- что делать с данными на устройстве, которое отключили с другого устройства;
- открыта ли регистрация на сервере;
- какой лимит места на аккаунт;
- оставлять ли старые публичные журналы GitHub Actions;
- защищать ли основную ветку;
- как проверять известную ошибку демо-стенда DSEditor.

## Решения

1. **Отключённое устройство стирает свои данные.**
   - Срабатывает, когда сервер однозначно сообщил, что сеанс устройства отозван. Временная ошибка сети и истёкший токен так не считаются.
   - Стирается всё, что хранит устройство: локальная база, ключи, вложения и кэш картинок. Неотправленные изменения тоже стираются: это цена защиты потерянного или украденного устройства.
   - После стирания показывается сообщение: «Это устройство отключено от аккаунта с другого устройства. Данные на нём удалены. Войдите снова — заметки загрузятся с сервера».
   - Предупреждение показывается заранее, там, где отзыв запускают:
     - «Завершить сеанс» в списке устройств: «Все данные на этом устройстве будут удалены, включая неотправленные изменения»;
     - смена пароля (она отключает другие устройства): «Другие устройства будут отключены, данные на них удалены»;
     - восстановление по ключу (отключает все устройства).
   - Сервер различает причины отзыва: пользователь, смена пароля, восстановление, повтор refresh-токена (признак кражи). Клиенты стирают данные при любой из них. Точные коды ответа и закрытия WebSocket описаны в `api.md` и `sync-protocol.md`.
   - Это **заменяет** правило от 2026-10-26 в `spec/07`: раньше данные на отключённом устройстве хранились до следующего входа.
2. **Регистрация остаётся открытой** (`DS_SIGNUP=open`, по умолчанию). Режимы `closed` и `invite` есть в сервере, их можно включить позже без новой сборки.
3. **Лимит места — 10 ГБ на аккаунт** (`USER_STORAGE_QUOTA_BYTES`, по умолчанию). Меняется настройкой сервера.
4. **Журналы старых ручных запусков `deploy.yml` удалены** (15 запусков). Режим inspect отключён в публичном репозитории.
5. **Основная ветка защищается**: удаление `main` и force-push запрещены, прямые push координатора остаются, подтверждение каждой выкладки не требуется. Включается владельцем в настройках GitHub (Settings → Rules → Rulesets): у ИИ-сессий нет прав на настройки репозитория.
6. **Известная ошибка демо-стенда DSEditor** (два теста касаний): тесты запускаются каждый раз. При падении появляется заметное предупреждение (`::warning` и строка в сводке), но проверка остаётся зелёной, если остальное прошло. Если тесты начнут проходить, появляется уведомление (`::notice`).

## Последствия

- Сервер: коды причины отзыва в HTTP 401 и при закрытии WebSocket.
- Core: событие «устройство отозвано» отличается от «нужно войти».
- Веб и iOS: стирание по этому событию, сообщение после стирания, предупреждения перед отзывом.
- Неотправленные изменения на отключённом устройстве теряются. Владелец это принял.
