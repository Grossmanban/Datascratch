# D-64. Сквозное шифрование и для ИИ-агентов: локальный мост

- **Статус:** РЕШЕНО (владелец продукта, 2026-11-08: «сервер не должен уметь читать даже блокноты для агентов» — делать). Детали ниже — **ПРЕДЛОЖЕНО** (поток agents), ждут подтверждения владельца через координатора.
- **Дата:** 2026-11-08
- **Связано:** D-04 (режим «для агентов»), D-10, D-11 (рукопись для агента — картинкой), D-30 (RLS), D-38 (OAuth), D-54 (ключи аккаунтов, обёртка для участника), D-57 (разрешение на все блокноты), D-62 (общие пространства), R-10; контракты `crypto.md` §8, §10, §12; `api.md` «Мост агента»; `agents-api.md` §11; `sync-protocol.md` §3, §6; `document-model.md` §2

## Контекст

Сейчас режим «для агентов» (`crypto.md` §8) устроен так: ключ блокнота обёрнут ключом сервера (`DS_KMS_KEY`). Агент приходит на сервер по MCP или REST, сервер расшифровывает заметки и отдаёт агенту открытый текст. Это удобно — работает даже Claude в браузере (claude.ai), — но сервер в этот момент видит всё содержимое таких блокнотов. Владелец хочет, чтобы сервер не мог прочесть даже блокноты, открытые агентам.

Агенту нужен открытый текст: модель читает и пишет заметки. Значит, расшифровывать должен кто-то на стороне агента, а не сервер.

## Решение

### Два режима «для агентов»

| Режим | Кто расшифровывает | Какие агенты | Значок |
| --- | --- | --- | --- |
| «для агентов» (как сейчас) | сервер | любые, в том числе claude.ai в браузере (удалённый MCP по OAuth) | ✨ |
| «для агентов, сквозное шифрование» (новый) | **мост агента** на компьютере агента | только через мост: Claude Code, Claude Desktop, любой агент, у которого есть свой компьютер или контейнер | ✨ с замком |

Приватный режим остаётся как есть. Блокнот в каждый момент в одном из трёх режимов (`document-model.md` §2, `mode: "private" | "agent" | "agent_e2e"`).

### Мост агента — `npx datascratch-agent`

Небольшая программа на Node.js — новый пакет монорепозитория `packages/agent-bridge` (npm-пакет `datascratch-agent`). Она:

- работает **на машине агента**: в облачной сессии Claude Code, на Mac рядом с Claude Desktop, на любом сервере с агентом;
- даёт агенту **те же инструменты MCP**, что и сервер сейчас (`agents-api.md` §3): по stdio (`npx datascratch-agent mcp` в настройках MCP агента) и, по желанию, по HTTP только на `127.0.0.1`;
- держит **ключ агента** — пару ключей X25519, как у аккаунта (`crypto.md` §12). Секретный ключ не покидает машину агента;
- скачивает с сервера **шифротекст** по протоколу синхронизации (как приложение), сам расшифровывает, сам шифрует правки агента и отправляет их как обычные зашифрованные обновления;
- рисует рукопись и картинки для агента **сам** (тот же код, что сейчас на сервере, `packages/agents`).

Код инструментов не пишется заново: мост запускает тот же `AgentService` из `packages/agents` поверх своего источника данных (`AgentDataSource`), который вместо «сервер расшифровал» делает «скачал шифротекст — расшифровал у себя». Криптография и синхронизация — из `packages/shared` (как у веб-приложения).

### Как агент получает ключи

Главный сценарий владельца — **Claude Code в облаке, запущенный с телефона**: контейнер сессии временный, диск исчезает вместе с сессией. Поэтому способов подключения два; по умолчанию — первый (решение владельца 2026-11-08: подтверждать каждую сессию — «морока»).

#### 1. Запомненный агент — подключить один раз (по умолчанию)

1. **На машине агента** (один раз): `npx datascratch-agent pair https://<сервер>`. Мост создаёт пару ключей и показывает **код подключения** (12 знаков, например `KQ7M-4ZPA-91XD`) и QR-код со ссылкой на приложение. Код — отпечаток ключа агента (`crypto.md` §12.2).
2. **В приложении (веб или iOS):** «Настройки → Агенты с доступом → Подключить агента» → ввести код (или навести камеру iPhone на QR). Приложение показывает имя агента и компьютера и **само проверяет**, что ключ агента, который прислал сервер, совпадает с кодом — сверять цифры вручную не нужно.
3. Владелец выбирает блокноты в режиме сквозного шифрования (или «все такие блокноты») и права («только чтение» / «чтение и правка») → «Разрешить». Приложение **само** оборачивает ключи выбранных блокнотов для ключа агента (сервер их не видит).
4. Мост, который всё это время ждёт, получает доступ и **один раз** печатает строку ключа агента: `DS_AGENT_KEY=dsa1.…` (адрес сервера, номер агента, токен и секретный ключ — `crypto.md` §12.1). Владелец сохраняет её:
   - для **Claude Code в облаке** — переменной в настройках облачного окружения Claude Code;
   - на **своём Mac** — мост сам кладёт ключ в Связку ключей (или в файл с правами `0600`).
5. Дальше **каждая новая сессия** запускает мост без вопросов: он читает `DS_AGENT_KEY`, скачивает шифротекст и работает.

#### 2. Подключение на одну сессию (по желанию, строже)

Для тех, кто не хочет хранить ключ агента у провайдера. Мост при каждом запуске создаёт **новую** пару ключей и ничего не пишет на диск. Владелец заранее один раз разрешает в приложении «запросы от облачных сессий» и кладёт в окружение не ключ, а **ключ запроса** (`DS_AGENT_ACCOUNT=…`): он позволяет только *попросить* доступ, читать с ним ничего нельзя. При запуске:

1. мост отправляет запрос; у владельца в приложении — уведомление «Claude Code (облако) просит доступ к „<блокнот>“» с кодом подключения; тот же код мост показывает в сессии;
2. владелец сверяет код (на телефоне он видит и сессию, и уведомление) и нажимает «Разрешить» — приложение оборачивает ключи для этого одноразового ключа;
3. доступ ограничен временем (по умолчанию 24 часа) и заканчивается раньше, когда мост сообщает, что сессия закрылась.

Цена строгости: после каждой такой сессии ключи её блокнотов меняются (§10.3: ключ побывал в чужом контейнере) — для небольших блокнотов это секунды работы приложения владельца.

#### 3. Обычный чат Claude через навык (проверить прототипом)

Обычный чат claude.ai (и на телефоне) умеет запускать код в песочнице. Идея: **навык** (SKILL.md + скрипт), который запускает мост в режиме командной строки прямо в песочнице чата — `datascratch-agent read|search|edit …`. Скрипт сам скачивает шифротекст с нашего сервера по токену агента и расшифровывает в песочнице; модель получает только результат, шифротекст через её контекст не проходит. Ключ агента лежит в навыке или проекте (у Anthropic — тот же уровень доверия, что у переменной окружения). Правки скрипт шифрует и отправляет сам; рукопись и картинки рисует сам.

Нужно проверить прототипом:
- **Сеть песочницы:** доступ к нашему серверу — через список разрешённых доменов в настройках claude.ai (владелец добавляет домен один раз). Без сети схема не работает.
- **Node или Python:** что доступно в песочнице и ставится ли npm-пакет. Если Node нет — минимальный перенос на Python: расшифровка конвертов (XChaCha20-Poly1305, PyNaCl), обёртки ключей, чтение Yjs (pycrdt) и Markdown — с теми же тестовыми векторами для совместимости; начать с «только чтение».
- **Правки:** скрипт собирает обновление Yjs, шифрует и отправляет его сам.
- **Рукопись и картинки:** рендер в песочнице.

Основной путь — мост в Claude Code; навык — третий вариант, если прототип подтвердит.

### Агенты с доступом (экран в приложении)

«Настройки → Агенты с доступом»: каждый агент — имя и машина, способ (запомненный / на одну сессию / навык), блокноты, права, «до» (для временных), **последний доступ** (сервер отмечает время последнего подключения моста), кнопка **«Отключить»**.

### Отзыв

«Отключить»: сервер сразу удаляет обёртки и токен агента и закрывает соединения моста, а ключи затронутых блокнотов меняются (`crypto.md` §10.3 — так же, как при удалении участника: агент видел ключи). Сохранённая строка `DS_AGENT_KEY` после этого бесполезна. Мост, потерявший доступ, стирает свои ключи и кэш.

### Что не меняется

- Режим «для агентов» через сервер остаётся: без него не работает claude.ai в браузере.
- Удалённый MCP на сервере (`/mcp`) и REST `/v1/agent/*` обслуживают только серверный режим. Блокноты со сквозным шифрованием сервер им не отдаёт и прочесть не может.

## Альтернативы

1. **Оставить как есть** (только серверный режим). Просто и работает в браузере, но сервер видит открытые агентам блокноты — владелец этого не хочет. Остаётся как второй режим.
2. **Мост на Python.** Многие агентские инструменты на Python, но тогда пришлось бы заново написать и поддерживать в двух языках криптографию, Yjs-модель документа (pycrdt отличается от yjs в мелочах), Markdown, раскладку рукописи и рендер. Мост на Node.js переиспользует всё готовое и проверенное векторами. Запуск через `npx` есть почти везде, где есть агент (Claude Code, Claude Desktop ставят Node сами).
3. **Мост внутри приложения** (агент подключается к открытому приложению пользователя). Работает только пока открыто приложение, на iPad фоновые серверы невозможны, на облачные агенты не распространяется. Не подходит.
4. **Дать агенту ключи аккаунта** (вход под пользователем). Агент получил бы все блокноты, отозвать его без смены пароля нельзя. Отклонено.
5. **Расшифровка на сервере в защищённом анклаве (TEE).** Сложно в эксплуатации на обычном VPS и требует доверять производителю железа. Не для этого этапа.

## Риски и честные ограничения

- **Ключ агента лежит у провайдера ИИ открытым текстом.** В основном сценарии строка `DS_AGENT_KEY` хранится в настройках облачного окружения Claude Code (у Anthropic) без шифрования; на Mac — в Связке ключей или в файле. Но и расшифрованный текст заметок, с которым агент работает, провайдер всё равно видит — уровень доверия к провайдеру тот же. **Наш сервер по-прежнему не видит ничего.** Смягчение: ключ даёт доступ только к выбранным блокнотам; права «только чтение» по умолчанию для новых подключений; «последний доступ» в списке агентов; «Отключить» мгновенно закрывает доступ и меняет ключи блокнотов; кто хочет строже — подключение на одну сессию. Что агент успел прочесть до отзыва, отнять нельзя — как с участником.
- **Провайдер ИИ всё равно видит текст.** Агент — это модель: всё, что он читает, уходит провайдеру модели. Сквозное шифрование защищает от **нашего сервера** (и от того, кто его взломает), а не от провайдера ИИ. Это говорится в интерфейсе при включении режима.
- **Нет поиска агента на сервере.** Сервер не может искать в зашифрованном: мост скачивает блокноты и строит индекс у себя. Первый запуск на большом блокноте медленнее (скачивание и расшифровка всех заметок); дальше — догоняющая синхронизация.
- **Не работает в браузере.** claude.ai в браузере не может запустить мост — для него только серверный режим. Приложение объясняет это при выборе режима.
- **Мост — ещё одна программа, которую надо обновлять.** Версия моста проверяется при подключении; старый мост получает понятную ошибку «обновите `datascratch-agent`».
- **Общие блокноты.** В первой версии ключ сквозного режима для агента выдаёт только **владелец** блокнота; агенты участников (D-54, поправка 2026-10-28) работают с общими блокнотами только в серверном режиме. Вопрос открыт (`open-questions.md`).

## План работ (предложение)

| Порядок | Поток | Что делает | Как проверяется |
| --- | --- | --- | --- |
| 1 | **core** (`packages/shared`) | обёртка ключа для агента (`crypto.md` §12), код подключения из ключа агента; `mode: "agent_e2e"` в контрактах; запись доверия `agent|…`; вход моста в протокол синхронизации (`auth.kind = "agent"`) в `SyncClient` | векторы `crypto/agent.json` (TS и Swift), юнит-тесты |
| 2 | **server** | режим `agent_e2e` у блокнотов (без серверной обёртки); таблицы сопряжений и обёрток агента; эндпоинты сопряжения, обёрток, отзыва (`api.md`); вход `agent` в синхронизацию с правами по разрешению (RLS); `agentKeys` в запросах смены ключа; `keyRotationPending` при отзыве; уведомление `account_changed: agents`; удалённый MCP не отдаёт блокноты `agent_e2e` | тесты API на PostgreSQL, в том числе отзыв, смена ключа, попытка читать чужое |
| 3 | **agents** (мы) | пакет `packages/agent-bridge`: CLI `pair`, `mcp`, `serve`, `status`, `unpair`; строка `DS_AGENT_KEY`; источник данных поверх `SyncClient`; локальный индекс поиска; хранение ключа (Связка ключей, файл, переменная); инструменты и рендер из `packages/agents`; затем подключение на одну сессию | сквозной тест: сервер + имитация приложения (подключение, обёртки) + мост по MCP → владелец видит правку агента; новая «сессия» с той же `DS_AGENT_KEY` работает без вопросов; отзыв → мост теряет доступ, ключ меняется |
| 3 | **agents** (мы) | **прототип навыка для чата claude.ai**: проверить сеть песочницы, Node/Python, чтение одной заметки; при необходимости — минимальный перенос расшифровки на Python с общими векторами | отчёт по прототипу: что работает в песочнице, что нет |
| 3 | **web-app**, **ios-app** | выбор из трёх режимов блокнота; экран «Агенты с доступом» (кто, машина, способ, блокноты, права, до, последний доступ, «Отключить»); «Подключить агента» (код или QR, проверка кода по ключу, блокноты, права); уведомление-запрос для подключения на одну сессию; обёртки для агента при добавлении блокнота и при смене ключа | e2e в вебе против сервера; UI-тесты iOS |
| 4 | **coordinator** | инструкция для пользователя (`guides/connect-ai-agents.md`), сборка и публикация npm-пакета | проверка на чистой машине: `npx datascratch-agent pair` → Claude Code читает заметку |

Шаги 3 идут параллельно после 1–2. До готовности шага 2 мост проверяется против сервера из ветки server.
