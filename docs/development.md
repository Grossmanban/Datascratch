# Процесс разработки

Решения: D-19 (код пишет Claude), D-23 и D-29 (документация и Graphify), D-28 (облако + Mac, CI).

## Кто что делает

- **Пользователь** — автор и владелец продукта: принимает решения, проверяет результат (прежде всего ощущение пера на iPad), открывает Mac для сборки и установки на iPad.
- **Claude** — пишет весь код и документацию, предлагает решения с рекомендацией, ведёт `docs/` и граф.

## Две среды

| Среда | Что есть | Что делаем |
| --- | --- | --- |
| Облачная сессия Claude Code (Linux) | Node.js, pnpm, Python, Graphify; **нет Xcode** | Документация, сервер, веб, написание iOS-кода |
| Mac пользователя (Apple Silicon) | Xcode, симулятор, iPad с Apple Pencil Pro по кабелю/сети | Сборка iOS, запуск, установка на iPad, проверка пера |

iOS-код, написанный в облаке, проверяет **GitHub Actions на macOS** (появится на этапе 1 вместе с Xcode-проектом). Xcode-проект описывается текстом через XcodeGen (`apps/ios/project.yml`, ПРЕДЛОЖЕНО) — его можно править без Xcode.

## Git

- Код, коммиты, идентификаторы — по-английски; документация — по-русски.
- Изменения — в отдельных ветках, в основную ветку через pull request.
- Один коммит = код + документация + обновлённый граф (см. «Определение готово» в `CLAUDE.md`).

## Graphify

Граф знаний по документации и коду. Главный инструмент навигации для ИИ (D-29). Пакет на PyPI — `graphifyy` (с двумя «y»), команда — `graphify`. Проверено на версии 0.9.95.

### Что где лежит

| Путь | Что | В git |
| --- | --- | --- |
| `graphify-out/graph.json` | Граф целиком | Да |
| `graphify-out/GRAPH_REPORT.md` | Обзор: ключевые узлы, сообщества, неожиданные связи | Да |
| `graphify-out/graph.html` | Интерактивная визуализация (открыть в браузере) | Да |
| `graphify-out/manifest.json`, `cache/` | Состояние для инкрементальных обновлений | Да |
| `graphify-out/.graphify_python`, `.graphify_root` | Пути на конкретной машине | Нет (`.gitignore`) |
| `.graphifyignore` | Что не попадает в граф (`docs/history/`, `.claude/`) | Да |
| `.claude/skills/graphify/` | Навык `/graphify` для Claude Code | Да |
| `.claude/settings.json` | Хуки: подсказки «сначала спроси граф» + стартовый хук | Да |

### Команды

```bash
graphify query "как устроен живой штрих"   # вопрос к графу
graphify explain "PostgreSQL"              # узел и его связи
graphify path "Yrs" "TextKit 2"            # путь между понятиями
graphify update .                          # обновить граф по коду (без ИИ, бесплатно)
graphify check-update .                    # отстал ли граф от документов
```

В сессии Claude Code:

```
/graphify . --update     # обновить граф по изменённым документам (семантический проход)
/graphify .              # полная пересборка
```

### Почему два способа обновления

- **Код** разбирается локально по синтаксису — быстро и бесплатно (`graphify update .`). Это же делает git-хук после каждого коммита.
- **Документы** нужно «понять» — это делает ИИ сессии (`/graphify . --update`). git-хук документы **пропускает**, поэтому обновление графа после правки документов — обязательный шаг перед коммитом.

### Автоматизация

- **Стартовый хук Claude Code** (`.claude/hooks/session-start.sh`, запускается в начале каждой сессии): ставит Graphify, если его нет; ставит git-хук; сообщает, если граф отстал.
- **git-хук** (`graphify hook install`): после коммита, checkout, merge пересобирает кодовую часть графа. Хуки git не хранятся в репозитории — их ставит стартовый хук в каждой новой среде.
- После `git pull` на Mac: `graphify update .` (pull не вызывает хук).

### Установка на Mac (один раз)

```bash
brew install uv            # если нет uv
uv tool install graphifyy  # поставит команду graphify
```

Дальше стартовый хук Claude Code сделает остальное сам.
