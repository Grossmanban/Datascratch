# ios-core-01 — 2026-10-25: ядро данных iOS (DSCore)

Сессия-исполнитель потока **ios-core** (D-39). Ветка `claude/ios-core`, зона — `apps/ios/Packages/DSCore`, `.github/workflows/ios-core.yml`.

## Что сделано

1. **Yrs в Swift (D-27).** Готовая обёртка `y-crdt/yswift` не подошла: нет XML-типов (`XmlFragment`/`XmlElement`/`XmlText`), нет относительных позиций, старая yrs 0.18, проект не развивается. Сделана своя обёртка через UniFFI 0.32 — Rust-крейт `apps/ios/Packages/DSCore/yrs-ffi`:
   - крупнозернистый API: один `YDocument`, узлы по путям (индексы детей / ключи вложенных карт), пакет операций в одной транзакции, снимки дерева, наблюдатели (`update`, `observeDeep` с путями и дельтами), отмена (только origin `local`), относительные позиции (кодирование, разрешение с признаком «символ удалён», перепривязка после отмены);
   - текстовые смещения — UTF-16 (как Yjs и `NSString`);
   - совместимость с Yjs/y-prosemirror проверена в обе стороны (`yrs-ffi/compat`, `tests/yjs_compat.rs`), байты относительных позиций совпадают.
2. **Найден баг yrs** (0.25–0.28): при следовании redone-элементу терялось смещение внутри элемента — якорь в середине куска текста после «удалить → отменить» съезжал на начало куска. yrs 0.25.0 вендорена с минимальным патчем (`yrs-ffi/vendor/PATCHES.md`), поведение сверено с Yjs.
3. **Сборка.** `scripts/build-xcframework.sh` (iOS-устройство, симулятор, macOS) → `build/yrs_ffiFFI.xcframework` (binaryTarget). Для облачных сессий — `scripts/build-linux.sh`: пакет собирается и тестируется на Linux (Swift 6.3 из swift.org, libsodium, sqlite), что ускорило работу на порядок; macOS-CI подтверждает.
4. **Модель документов**: `NoteDocument` (блоки, inline-правки, задачи, meta, штрихи, комментарии, восстановление версий), `NotebookDocument`, `AccountDocument`, производные данные (как в `extract.ts`), канонический PM-JSON, Markdown-экспорт (порт `markdown.ts`, байт в байт).
5. **Штрихи**: кодек точек, кривая толщины, разбиение на сегменты (D-35, разрыв по строкам), перепривязка якорей после отмены/повтора и при восстановлении версии (`strokes.md` §4.1), учёт осиротевших штрихов и их удаление перед снимком (§4.2).
6. **Криптография** (`crypto.md`) на Clibsodium из swift-sodium: Argon2id, конверты, обёртки ключей, ключ восстановления (Crockford Base32), куски вложений; `KeyRing` + Keychain.
7. **Локальное хранилище** (GRDB): обновления, очередь отправки, состояние синхронизации, индексы задач/бэклинков/тегов, FTS5-поиск (префиксы, без диакритики), вложения, осиротевшие штрихи.
8. **Сеть**: `APIClient` (все эндпоинты `api.md`, обновление токенов), `SyncClient` (WebSocket, переподключение, пинги), `SyncEngine` (шифрование, офлайн-очередь, регистрация документов, снимки по порогам, awareness), `AccountService` (регистрация, вход, восстановление, смена пароля, создание блокнотов и заметок), `AttachmentManager` (куски с докачкой).
9. **Тесты**: 52 теста (Swift Testing) + 13 Rust-тестов: все общие векторы `packages/test-vectors` (crypto, ids, strokes, document, sync), фейковый сервер синхронизации и REST-сервер для сквозных сценариев. CI `ios-core.yml`: Rust + проверка Yjs + свежесть привязок (Ubuntu), xcframework + `xcodebuild test` на симуляторе iPad iOS 26 (macos-26).

## Что решили / предложили координатору

- Своя UniFFI-обёртка вместо yswift (сообщено координатору; ADR — на усмотрение координатора, номер не занимаю).
- Уточнения контракта `document-model.md` §4.1 (метки `{}`, наследование форматирования при вставке, отсутствие null-атрибутов) — приняты координатором.
- Перепривязка якорей после отмены делается отдельной транзакцией сразу после шага отмены (Yrs открывает собственную транзакцию для undo); redo при этом не ломается.

## Продолжение сессии

- Влито координатором в `main` дважды; решение по Yrs оформлено как D-42.
- `yrs_ffiFFI.xcframework` публикуется релизом `yrs-ffi-<хэш>` и закреплён в `Package.swift` — потребителям Rust не нужен.
- По уточнению протокола: push только после `subscribe` и `upToDate` по документу; код `bad_request`, `Session.deviceId`, `mime` вложений.
- Хелперы штрихов в транзакциях для ios-editor; ежедневные заметки и «Входящие» для ios-app.
- Бенчмарки spec/11: первая синхронизация 10 000 заметок ≈ 22 с (цель ≤ 60), открытие заметки на 10 000 слов ≈ 10 мс (≤ 300), холодный старт ≈ 0,5 с (≤ 1); приём обновлений — одна транзакция на документ, пакетная индексация.

- Снимок при закрытии после ≥ 30 локальных правок; проверка тел REST (`api/bodies.json`), строгий base64url; `moveNote` между блокнотами; векторы `share-link`, `signup-flow`.
- Холодный старт на симуляторе iOS был 1,8 с: чтение записей через NSDictionary медленное. Добавлен `map_json` в yrs-ffi и разбор записей через JSONDecoder; закреплён релиз `yrs-ffi-cfa579e9c35b`.
- Замеры на симуляторе iPad: первая синхронизация 10 000 заметок ≈ 26 с с индексацией, заметка на 10 000 слов ≈ 12 мс, холодный старт ≈ 0,37 с — все цели spec/11 выполнены.
- Тест снимка упал на симуляторе по таймауту: каждая правка запускала отдельный проход по очереди отправки (O(n²) при массовых правках). Проходы теперь объединяются — тест 5 с → 1,8 с на Linux.

- Ротация ключа восстановления и журнал безопасности (по поручению координатора): `rotateRecoveryKey`, `securityEvents`, `AccountDocument.recoveryKeyConfirmed`; кнопку в настройках делает ios-app.

- Ленивые документы по образцу TS SyncClient (поручение координатора): снимок закрытых документов слиянием обновлений, awareness только для открытых, исправлена гонка `close`/`open` (тест при непрерывной записи), окно отправки ограничено 100 сообщениями в ожидании `ack` (из-за прежнего окна тест снимков иногда не досылал хвост очереди), бенчмарк памяти.

- Индекс задач: поле `order` (и `completedAt`) по обновлённому вектору `document/note.json`, миграция с заполнением порядка.

- Индексация и фон (одобрено координатором, пункты 1, 2, 4): инкрементальная параллельная индексация, `syncOnce` для `BGAppRefreshTask`. Идея тихих пушей (APNs) передана координатору для `open-questions.md`.

- По запросу ios-app (зависание «Синхронизация…» в build 5): политика недоставляемых сообщений — `SyncStatus.failed`, `retryFailed`/`discardFailed`, полное `deleteDocument`, миграция `v6-outbox-failed`.

Тесты: короткая правка + уход → версия (и не вторая через минуту; фон через 2 мин → вторая), 10 минут правки → версия, перед подсказкой → версия с текстом «до».
