# 2026-10-25 — поток server, сессия 01

## Что сделано

- `apps/server`: сервер целиком по контрактам `api.md`, `sync-protocol.md`, `crypto.md` — авторизация (серверный Argon2id над loginKey, фальшивая соль, ротация refresh-токенов с обнаружением повторного использования, JWT через jose), восстановление, смена пароля, устройства, удаление аккаунта; блокноты и режимы (обёртка ключа `DS_KMS_KEY`); регистрация документов, история версий; вложения кусками (диск по умолчанию, S3 по настройке); шеринг и гостевые токены; токены агентов и журнал.
- Синхронизация: WebSocket `/v1/sync`, seq под блокировкой строки документа, идемпотентный `push` по `clientMsgId`, догоняющая подписка страницами, упорядоченная живая рассылка (пропуски дочитываются из базы), awareness, снимки, уплотнение и политика хранения истории, лимиты, права user/guest, мгновенное отключение при отзыве.
- PostgreSQL: схема Drizzle + миграции; Row-Level Security для агентов (роль `ds_agent`); триггер очистки файлов.
- pg-boss: уплотнение, очистка, ежедневный проход по истории.
- Интерфейс плагина для потока agents (`apps/server/src/plugins/api.ts`, описание — `apps/server/README.md`): проверка токена, RLS-транзакция, чтение/запись документов с шифрованием, ключи, вложения, аудит, очередь.
- Тесты: 36 (vitest + настоящий PostgreSQL), в т. ч. синхронизация двумя–четырьмя клиентами, порядок при параллельной записи, гости, RLS при «забытых» проверках в коде.
- `infra/`: Dockerfile, `docker-compose.yml` (сервер + PostgreSQL, профиль `https` с Caddy), `backup.sh`/`restore.sh`, `smoke-test.sh` (копия → полное стирание → восстановление → вход), `infra/README.md` — пошаговая инструкция для Hetzner.
- CI `server.yml`: сборка, typecheck, lint, проверка миграций, тесты с PostgreSQL, сборка образа и smoke-тест compose. Зелёный.

## Что решили (ПРЕДЛОЖЕНО, в `spec/06`)

Политика хранения истории (7 дней всё, затем день/неделя/месяц), хранение покрытых снимком обновлений 7 дней, отзыв других устройств при смене пароля, деление шеринга блокнота на все его заметки, `protocol_mismatch` для некорректных сообщений.
