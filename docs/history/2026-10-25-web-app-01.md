## Стык с агентами (agents-api.md §8, §10)

- Страница `/connect?returnTo=…`: ставит браузерную сессию сервера (`POST /v1/auth/web-session`, cookie `ds_web`) и возвращает на экран согласия OAuth; цель возврата — только `/oauth/authorize` того же сервера.
- «Настройки → Агенты»: адрес `<сервер>/mcp` с копированием, токены и OAuth-подключения одним списком, журнал в новом формате, токен показывается один раз.
- В `meta` документа блокнота клиент копирует `name`, `icon`, `space` (обновляется при любом изменении аккаунта).
- `hello.deviceId` берётся из `Session.deviceId`.

## Что решили (технически, в зоне потока)

- Мастер-ключ между перезагрузками хранится зашифрованным неизвлекаемым ключом WebCrypto в IndexedDB; обновления Yjs на устройстве лежат расшифрованными (устройство доверенное, как у Notesnook без «блокировки приложения»).
- Заглушки чужих пакетов подключаются через одну точку (`src/lib/shared.ts`, `src/ui`, `src/editor`).
- Аккаунт-документ дополнительно регистрируется `POST /v1/docs` (идемпотентно), если сервер не делает этого при регистрации.

## Вопросы координатору

1. История версий: сервер не может собрать состояние на `seq` из шифра. Предложение: версии = снимки, загруженные клиентами; веб дополнительно шлёт `snapshot` при уходе из документа после ≥ 30 правок. Нужно закрепить в контракте.
2. Перенос заметки между блокнотами: нет API смены блокнота документа (`PATCH /v1/docs/:id { notebookId }`) и переобёртки ключа заметки. Пока перенос — только внутри блокнота.
3. Регистрирует ли сервер `account`-документ при `signup`? (Проверено на `apps/server`: повторная регистрация клиентом безвредна.)
4. Для web-editor: при смене пропа `awareness` редактор пересоздаётся, а `BubbleToolbar` в cleanup обращается к `editor.view.dom` уже уничтоженного редактора (исключение TipTap). В вебе обойдено (редактор монтируется после создания присутствия).
5. ~~Синхронизация своя~~ — переведена на `SyncClient` (см. ниже).

## Переход на SyncClient

- Свой движок (`src/sync/engine.ts`) удалён, остался только статус для интерфейса. Протокол ведёт `SyncClient` из `@datascratch/shared/sync`.
- `DexieSyncStorage` — реализация `SyncStorage` на IndexedDB (пакетные `getDocStates`/`setDocStates`). Версия базы 4: старая очередь `outbox` переносится в `syncOutbox` при обновлении (тест `dbUpgrade.test.ts`).
- Гостевая сессия — тот же `SyncClient` с `MemorySyncStorage`. Присутствие шифрует сам клиент (`sendAwareness`).
- Найдено: libsodium нужно инициализировать до первого шифрования в `SyncClient`; браузер держит WebSocket открытым при отключении сети — переподключение по событию `offline`.
- e2e 10/10 против мок-сервера и против настоящего `apps/server`.
