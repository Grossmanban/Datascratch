# 2026-10-26 — ios-app, сессия 02 (продолжение)

## Дубли пространств у пользователя (build 6)

- В вебе у пользователя два «Личное» и «Работа»: build 6 перенёс локальную библиотеку без слияния, а слияние в build 7 срабатывало только сразу после переноса.
- Теперь `mergeCarriedDuplicates` запускается при каждом старте синхронизации (идемпотентно). Без свежего переноса сливаются только пространства со стартовыми именами («Личное», «Работа»), чтобы не трогать одноимённые пространства, созданные намеренно. Остаётся пространство с бо́льшим числом блокнотов.
- Тест `startAfterABuild6CarryMergesTheTwins`: перенос как в build 6 → старт → дублей нет, повторный запуск ничего не меняет.
- Не закрыто: два одноимённых блокнота с содержимым в обоих не сливаются. Перенос заметки между блокнотами в серверном режиме не сообщает серверу (`PATCH /docs/:id`) — поэтому заметки не переносятся автоматически; это отдельный риск.

## Перенос заметки между блокнотами → сервер

- `CoreLibrary.moveNote` теперь обновляет запись документа (`store.setNotebook`), ставит перенос в очередь (`pendingMoves`, в хранилище) и сообщает `CoreLibraryRemote.noteMoved` → `PATCH /docs/:id` (api.md «Перенос заметки»). 404 для незарегистрированного документа — снимается (регистрация придёт с новым блокнотом), для зарегистрированного — создаётся недостающий блокнот и запрос повторяется. Неотвеченные переносы отправляются на следующем старте.
- `mergeCarriedDuplicates` объединяет одноимённые «Заметки», если в обоих есть документы: заметки переезжают в ежедневный (или самый наполненный), задачи «Входящих» сливаются в одни. Блокноты с папками не трогаются.
- Тесты: `movingANoteTellsTheServer`, `twinNotebooksWithNotesBecomeOne`.

## «Устройство отключено» вместо тихой паузы

- Отзыв пользователя: если сеанс завершён из другой сессии, приложение должно сказать это явно.
- Признак отзыва — `APIError.notAuthenticated` при получении токена для WebSocket (refresh отклонён с 401; сеть и 5xx дают `transport`/`server` и сюда не попадают). `ServerConnection.sessionEnded()` останавливает движок, ставит `SyncCenter.markSessionEnded()` и запоминает флаг в хранилище, чтобы следующий запуск тоже показал отключение, а не экран приветствия.
- `SessionEndedView`: «Это устройство отключено от аккаунта», пояснение, e-mail и пароль, «Войти» / «Позже»; в индикаторе — «Устройство отключено» с кнопкой «Войти». Вход тем же аккаунтом не трогает библиотеку и ключи (документ аккаунта тот же, `adoptAccount` ничего не переключает).
- Тесты: `SyncCenterTests.anEndedSessionIsNotOverwrittenByTheEngine`, UI `SessionEndedUITests` (`-ui-testing-session-ended`).
- Дата отзыва не показывается: ответ refresh её не содержит.

## iPad: двойной список и подвал сайдбара (отзыв build 8)

- Двойной список: закрытие документа ставит «список на весь экран» (`isContentFullScreen` + `.detailOnly`); если затем открыть сайдбар системной кнопкой, раскладка меняется, а флаг оставался — detail показывал второй экземпляр списка. Теперь любой выход из `.detailOnly` сбрасывает флаг, а detail показывает список только при `.detailOnly`; ⤡ «Показать колонки» — только в настоящем полноэкранном режиме.
- Подвал сайдбара: `safeAreaInset` не отодвигал конец списка — «Корзина» уходила под плашку. Подвал теперь поверх списка, а у списка нижний отступ содержимого равен высоте подвала (`contentMargins`).
- UI-тесты `testNotebookListShowsOnceOnIPad(+Landscape)`.

## Колонки iPad по новому правилу (D-15) и «Очистить корзину»

- «Пусто» в шапках колонок оказалось кнопкой корзины «Empty» (переведена как прилагательное), а не служебным элементом тулбара. Теперь «Очистить корзину» с иконкой, danger, неактивна при пустой корзине, подтверждение с числом документов. Проверены другие омонимы (Open/Close/Clear/Copy/Done) — ошибок нет; «Empty» в календаре (пустой день) — прилагательное, оставлено.
- Колонки iPad переписаны: `NavigationSplitView` из двух колонок (сайдбар | рабочая область), рабочая область сама раскладывает список и документ (`PadWorkspace`). Сайдбар — только своя кнопка `SidebarToggleButton` (системная убрана), состояние `isSidebarShown` запоминается. Открытие/закрытие документа сайдбар не трогает; без документа список на всю ширину рабочей области; если рабочая область уже 640 pt (портрет с сайдбаром), документ показывается один, список возвращается при закрытии. «На весь экран» (`fullScreen: .document / .content`) прячет сайдбар и список; выход возвращает прежнюю раскладку. iPhone и узкое окно — прежний трёхколоночный стек.
- UI-тесты: `testColumnRulesOnIPad(+Landscape)`, переписан `testContentFullScreenOnIPad(+Landscape)`; тесты с выбранной ориентацией больше не переворачиваются в альбом при запуске.
- Нужна запись решения в `docs/decisions` (замена правила «сайдбар прячется при открытии документа») — передано координатору.
- Исправления после прогона 40289837269: кнопки сворачивания палитры — системный стиль .glass (простая кнопка поверх интерактивного стекла не получала нажатие и не показывала иконку); тесты: фокус на поле палитры команд, прокрутка сайдбара до конца перед проверкой подвала.

## «Устройство отключено» по spec/07 (build 10)

- `CoreLibrary.wipeLocalData()`: все документы, ключи (новый мастер-ключ устройства), отложенные переносы, оверлей; новый пустой документ аккаунта устройства.
- Вход ДРУГИМ аккаунтом после отключения (e-mail не совпадает с сохранённым при отключении): на экране — предупреждение и подтверждение «Удалить и войти»; `ServerAccountService.signIn` чистит локальные данные до входа — ничего от прежнего аккаунта не попадает в новый (и перенос D-43 нечего переносить).
- «Удалить данные с этого устройства» с подтверждением → `deleteLocalData()` → экран приветствия.
- Счётчик «Неотправленные изменения сохранены на этом устройстве: N» (последнее известное `pendingChanges`).
- Unit-тест `wipingLocalDataLeavesNothingBehind`.
- Подэкраны «Устройства», «Перо и рисование», «Внешний вид», «Сменить пароль» — на DSSettingsSection/Row (переключатели, выбор галочкой, поля строками, ошибка — DSCallout). Ключ восстановления, журнал и «О программе» — пока прежние.
- `CoreLibrary.writeNotebookMeta` → `NotebookDocument.setMetaCopy` (цвет, без записи при неизменных данных); тест `notebookMetaCarriesNamesForAgents` проверяет цвет и переименование пространства.
