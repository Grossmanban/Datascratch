# 2026-10-27 · ios-app · сессия 04 — build 20 и аудит безопасности (build 21)

- Build 20 ушёл из c79e995 (iOS = 1d1b6ae): вставка картинок из веб-страниц через `AttachmentManager.add(id:)`, ветка ios-editor e6d4acfb+.
- Build 21, ветка claude/ios-app-21 от main (10496307). Аудит координатора проверен по коду — все пункты подтвердились:
  1. `NoteMedia.share`: имя из блока и id в пути `tmp/<id>/<name>` → `SafeFileName.sanitize` + `UUIDv7.isValid`; `CoverImages.url(_:)` возвращает nil для не-id (image/file/fetch/remove/store).
  2. `CoreLibrary.wipeLocalData(attachments:)` удаляет записи вложений (pendingUpload/synced/remote) и файлы; `deleteLocalData` сначала `api.logout()`; `ServerConnection.onLocalDataWiped` → `CoverImages.forgetAll()` (и при входе в другой аккаунт).
  3. `SecretPasteboard.copy` (`.localOnly`, `.expirationDate` +60 с): ключ восстановления (онбординг, настройки), токен агента, ссылки шеринга.
  4. «Показать ключ» — `DeviceOwner.authenticate` (LAContext, без код-пароля — пропуск); `RecoveryKeyGrid.hiddenWhenCaptured()` (`sceneCaptureState`).
  5. `CoverImages.jpeg(Data)` / `downscaled` — ImageIO-миниатюра с `kCGImageSourceThumbnailMaxPixelSize`, отказ >50 Мп по свойствам до декодирования, `Task.detached`; `image(_:)` читает файл тем же путём (до 2560 px); вставка из буфера — байты файла (`pastedImageData`), а не `UIImage`.
  6. `RemoteImageFetcher`: эфемерный сеанс, https, ≤20 МБ (AsyncBytes), 15 с, ≤3 перенаправления (`RedirectGuard`), `getaddrinfo` + `isPublic` (IPv4/IPv6, ::ffff:), ≤50 картинок за вставку.
- Тесты `SecurityAuditTests` (имена, id, стирание вложений, буфер, отказ 100 Мп по заголовку PNG без пикселей, масштаб, адреса, https/локальные хосты).
