# 2026-10-27 — поток server, сессия 01

## Что сделано

- **Аудит безопасности сервера** (высокие, средние и низкие пункты), всё с тестами:
  - синхронизация: ограничение кадров до `hello`, лимиты соединений на адрес и на аккаунт, частота сообщений до разбора, ограниченные по байтам пачки при подписке;
  - гостевые ссылки закрываются у открытых соединений, когда истекает срок;
  - квота 10 ГБ на аккаунт (триггеры), `DS_SIGNUP`, ограничения картинок для агентов;
  - защита `fetch-image` от SSRF;
  - `retryAfterMs` у всех ответов `rate_limited`.
- **Инфраструктура:**
  - закреплённый ключ сервера;
  - `permissions` в workflow, actions и образы закреплены по SHA/digest;
  - веб-контейнер не от root;
  - `restore.sh` проверяет копию и сохраняет текущие данные.
- **D-53 — отзыв устройства:** HTTP `401 device_revoked` с причиной; синхронизация — `error device_revoked` и закрытие 4410; миграция 0005.
- **D-55 — простые бэкапы:** команда `/opt/datascratch/ds` (`backup`, `backups`, `restore`, `key`, `key-saved`); rclone убран; `DS_KMS_KEY` выводится только в терминал.
- **D-49 — адрес не виден в публичных журналах:**
  - `infra/deploy/address.sh`: источник — секрет `DS_DOMAIN`, без него — домен, с которым сервер уже работает, на новом сервере — `…sslip.io` из IP;
  - значение маскируется сразу;
  - в Summary адреса нет.
- **D-54 — совместный доступ, серверная часть** (миграции 0006–0007):
  - пара ключей аккаунта, приглашения, участники с ролями, «Общие со мной» и `/shared-by-me`;
  - смена ключа: в `rotate` — ровно активные участники, `rotate/done`, ключ заметки для владельца, `pendingSinceVersion`;
  - автор каждого обновления, авторы версий при снимке;
  - квота на владельце;
  - аккаунт, созданный после приглашения, получает доступ только после выдачи ключа владельцем.
  - Исправление по e2e веб-приложения: ресурс, из которого ушёл последний участник, остаётся в `/shared-by-me`, пока смена ключа не завершена.
- Продакшн-выкладки 3f2c5b55 и 58e3577d прошли: адрес везде скрыт, миграции применены, smoke зелёный.

## Что решили

- Владелец (через координатора):
  - D-54: гостевые ссылки после смены ключа программа создаёт заново;
  - D-54: аккаунт, созданный после приглашения, получает доступ только после подтверждения владельцем (на сервере подтверждение — выдача ключа);
  - адрес сервера настраивается без изменений в GitHub;
  - новый сервер без домена работает на sslip.io.
- С core:
  - `GET /shared-by-me` и `pendingSinceVersion`;
  - участник `awaiting_key` в смену ключа не входит;
  - `GET /members/note/:id/key` отвечает `404`, пока ключ заметки не менялся.
