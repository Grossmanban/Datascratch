## Этап 1 — прототип пера в тексте (iPad)

**Цель:** доказать, что «живой штрих» (D-05) работает и ощущается нативно. Если не убеждает — остальное не строим, пересматриваем подход.

### Подготовка

- [ ] iOS-проект в `apps/ios`, описанный через XcodeGen (`project.yml`) — подтвердить D-28.
- [ ] Минимальная версия iPadOS — зафиксировать.
- [ ] CI: GitHub Actions собирает проект и гоняет тесты на macOS.
- [ ] Подключить Yrs (Swift-обёртку) и проверить, что она собирается и работает на iPad (D-27).

### Состав прототипа

- [ ] Один экран: текстовый редактор на TextKit 2, текст хранится в Yrs, слой пера поверх.
- [ ] Ввод пером: coalesced и predicted touches, нажим, наклон; ластик.
- [ ] Пометки на тексте: подчёркивание, зачёркивание, обводка, маркер, свободный штрих поверх слов.
- [ ] Привязка точек к символам через относительные позиции Yrs и пересчёт при перекладке.
- [ ] Перекладка при повороте экрана, изменении ширины (Stage Manager / Split View) и правке текста.
- [ ] Разрыв штриха по строкам.
- [ ] Простейшее сохранение в файл — проверка восстановления после перезапуска.
- [ ] Выбор рендера пера: Metal или Core Animation (замер задержки и кадров).
- [ ] Решить: обводки вокруг нескольких слов, стрелки между словами на разных строках, судьба штриха на удалённом тексте (см. `open-questions.md`).

### Критерии приёмки

- Штрихи не «уезжают» с привязанных слов при повороте, смене ширины, вставке и удалении текста до и внутри помеченного фрагмента.
- Подчёркнутая фраза, переносящаяся на две строки, рисуется двумя частями.
- Субъективная задержка пера не хуже Apple Notes / PencilKit; стабильные 120 кадров/с при рисовании и прокрутке.
- Пользователь лично проверил на своём iPad (Pencil Pro) и подтвердил ощущение.

**Нужно от пользователя:** Mac с Xcode для сборки и установки на iPad; iPad с Apple Pencil Pro для проверки.
