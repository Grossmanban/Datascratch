# 9. API и внешние ИИ-агенты

Решения: D-04, D-10 (правки агента применяются сразу), D-11 (рукопись для агента — PNG).

Подключение через **удалённый MCP-сервер** (Streamable HTTP, вход по OAuth 2.1) и **REST API**. Встроенного ИИ нет, архитектура его не исключает. Доступны только блокноты в режиме «для агентов» (`07-encryption.md`).

## Агент умеет

- Искать и читать заметки — в Markdown; на месте рукописных фрагментов — **PNG-картинка** этого фрагмента и текстовая пометка, к чему он привязан («подчёркнуто от руки: …») (D-11: идея — РЕШЕНО, формат PNG — ПРЕДЛОЖЕНО; SVG — опционально для экспорта). Рендер делает сервер.
- Создавать заметки и править точечно — по блоку или фрагменту, не перезаписью целиком.
- Оставлять комментарии к фрагментам.
- Читать ссылки, теги, бэклинки, структуру пространств и папок.
- Наводить порядок: создавать папки (с подпапками любой глубины), переименовывать, перемещать и удалять их (только пустые или с переносом содержимого на уровень выше — заметки агент не удаляет), переносить заметки между папками и между своими блокнотами. **Блокноты агент не создаёт:** они шифруются мастер-ключом пользователя, которого у сервера нет; агент так и говорит и просит создать блокнот в приложении.

## Безопасность

- Токены и OAuth 2.1.
- Права на токен — чтение или чтение+запись, по конкретным блокнотам; дополнительно ограничиваются на уровне базы (PostgreSQL Row-Level Security, D-30).
- Общие блокноты (D-54): агенты участника видят общий блокнот, только если владелец включил у него режим «для агентов», и с правами участника («может редактировать» — чтение и запись, «только чтение» — только чтение). Правки подписаны как «агент <участник>», доступ пропадает сразу, когда владелец выключает режим или участник уходит из блокнота. Вынести заметку из общего блокнота агент участника не может.
- Журнал всех действий агента.
- Лимиты запросов.
- Общие блокноты (D-54): если владелец открыл общий блокнот агентам, участник подключает к нему **своего** ИИ с теми же правами, что у него самого — у редактора ИИ читает и правит, у читателя только читает (на попытку правки — понятная ошибка «только чтение»). Такие блокноты агент видит с пометкой «общий» и почтой владельца; заметку из своего блокнота в чужой (и обратно) агент не переносит.

## Правки агента (D-10)

Применяются сразу, подсвечиваются в интерфейсе, откатываются через историю версий. Новая заметка, созданная агентом, построчно не подсвечивается: в её начале полоска «Создано агентом» (D-45). Рукописные якоря не ломаются (они — относительные позиции CRDT).

## Инструменты MCP (реализовано, контракт — ЧЕРНОВИК)

Точное описание — контракт `docs/architecture/contracts/agents-api.md` (черновик потока agents, ждёт утверждения координатором).

| Инструмент | Что делает | Права |
| --- | --- | --- |
| `list_spaces`, `list_notebooks`, `list_notes` | Структура: пространства, блокноты, папки, заметки | чтение |
| `search_notes` | Поиск по заголовкам, тексту и тегам | чтение |
| `read_note` | Заметка в Markdown; у каждого блока — его `blockId`; на месте рукописи — картинка и пометка «подчёркнуто от руки: …» | чтение |
| `get_handwriting_image` | PNG рукописного фрагмента с окружающим текстом | чтение |
| `get_backlinks` | Кто ссылается на заметку, куда ссылается она | чтение |
| `list_tasks` | Задачи из всех доступных заметок с датами | чтение |
| `create_note` | Новая заметка из Markdown | правка |
| `edit_note` | Точечные правки по `blockId`: вставить, заменить, удалить, переместить блок, заменить фрагмент текста; атомарно | правка |
| `add_comment` | Комментарий к блоку или цитате | правка |
| `update_task` | Выполнить/отменить задачу, перенести дату или дедлайн | правка |
| `create_folder`, `rename_folder`, `move_folder`, `delete_folder` | Папки внутри блокнота, вложенные; удаление — только пустой папки или с переносом содержимого наверх | правка |
| `move_note` | Перенести заметку в папку или в другой блокнот агента (за один шаг, ключ заметки переобёртывается на сервере) | правка |

Те же операции доступны по REST: `/v1/agent/*`.

## Подключение

- **OAuth 2.1** (так подключаются Claude, ChatGPT и другие MCP-клиенты): агент сам находит сервер авторизации, регистрируется (Client ID Metadata Document или динамическая регистрация), открывает в браузере **экран согласия** Datascratch, где пользователь выбирает блокноты и права (только чтение / чтение и правка).
- Если сервер не может достучаться до сайта агента (например, claude.ai недоступен из региона сервера), Client ID Metadata Documents не объявляются (`OAUTH_CLIENT_METADATA_DOCUMENTS=false`, так по умолчанию в `infra/deploy`) — агент регистрируется динамически (RFC 7591), без исходящих запросов сервера.
- **Статический токен** из настроек (`/v1/agent-tokens`) — для агентов без OAuth и REST-скриптов.
- Все подключения видны в настройках одним списком; отзыв действует сразу. Журнал действий — по каждому подключению.
- Лимит — 120 запросов в минуту на подключение.

Инструкция для пользователя: `docs/guides/connect-ai-agents.md`.

## Реализация

Пакет `packages/agents` — Fastify-плагин, который сервер подключает в свой процесс. MCP — официальный TypeScript SDK v2 (спецификация MCP 2026-07-28, старые клиенты 2025 года поддерживаются). Слой MCP тонкий поверх общего сервисного слоя (REST и MCP вызывают одни и те же функции), потому что спецификация MCP быстро меняется (R-13). Рендер рукописи — `@napi-rs/canvas` со встроенными шрифтами.
