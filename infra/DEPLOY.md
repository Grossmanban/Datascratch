# Как развернуть сервер Datascratch на своём VPS без компьютера (GitHub Actions)

Сервер и веб-приложение собираются в GitHub Actions и сами выкладываются на ваш VPS по SSH. Нужен только браузер — можно с iPhone. Mac и терминал на своём компьютере не нужны.

Один раз сделать 4 шага (≈ 15 минут). Дальше каждое изменение в `main` выкладывается само, а при сбое сервер возвращается на прежнюю версию.

> Что понадобится: VPS с **Ubuntu 24.04** (2 ядра, 4 ГБ памяти — например, у российского хостинга или Hetzner Cloud CX22), доступ к его **веб-консоли** у провайдера и права администратора в репозитории на GitHub. Домен — по желанию: без него сервер получит адрес вида `203-0-113-10.sslip.io` с настоящим HTTPS-сертификатом.

---

## Шаг 1. Создать сервер

1. <https://console.hetzner.cloud> → проект → **Add Server**.
2. **Location** — любая в Европе; **Image** — **Ubuntu 24.04**; **Type** — **CX22** (или ARM **CAX11**).
3. **SSH keys** — можно не добавлять (ключ для деплоя создадим на самом сервере). Hetzner пришлёт пароль root на почту.
4. **Create & Buy now**. Запишите **IP-адрес** сервера (например `203.0.113.10`).

## Шаг 2. Создать отдельный ключ для деплоя — прямо на сервере

Ключ создаётся на сервере и нужен только GitHub для выкладки. Ваш личный доступ он не затрагивает.

1. В консоли Hetzner откройте сервер → вверху справа значок **>_ Console** (веб-консоль). Войдите как `root` с паролем из письма (при первом входе система попросит сменить пароль).
2. Вставьте по одной строке и нажмите Enter после каждой:

   ```bash
   ssh-keygen -t ed25519 -N '' -C github-deploy -f /root/.ssh/github_deploy
   cat /root/.ssh/github_deploy.pub >> /root/.ssh/authorized_keys && chmod 600 /root/.ssh/authorized_keys
   cat /root/.ssh/github_deploy
   ```

3. Последняя команда покажет **приватный ключ** — блок от `-----BEGIN OPENSSH PRIVATE KEY-----` до `-----END OPENSSH PRIVATE KEY-----`. Выделите его целиком вместе с этими строками и скопируйте. Это секрет `DEPLOY_SSH_KEY`.
4. Запомните отпечаток ключа сервера (пригодится в шаге 4):

   ```bash
   ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
   ```

   Строка вида `256 SHA256:AbCd… root@… (ED25519)`.

> Если копировать из веб-консоли неудобно, можно вывести ключ так: `cat /root/.ssh/github_deploy | tr '\n' '~'` и после вставки в секрет заменить `~` на переносы строк. Проще — скопировать как есть: GitHub принимает многострочные секреты.

## Шаг 3. Добавить секреты в GitHub

1. Репозиторий на GitHub → **Settings** → **Secrets and variables** → **Actions**.
2. Вкладка **Secrets** → **New repository secret**:

| Name | Значение |
| --- | --- |
| `DEPLOY_HOST` | IP-адрес сервера из шага 1 (например `203.0.113.10`) |
| `DEPLOY_SSH_KEY` | Приватный ключ из шага 2 целиком, включая строки `BEGIN` и `END` |
| `DEPLOY_USER` | необязательно: пользователь для входа (по умолчанию `root`; другой пользователь должен иметь `sudo` без пароля) |
| `DEPLOY_PORT` | необязательно: порт SSH (по умолчанию `22`) |

Названия — буква в букву.

## Шаг 4. Запустить

1. Вкладка **Actions** → слева **deploy** → справа **Run workflow** → **Run workflow**.
2. Первый запуск идёт ≈ 10 минут: сборка образов, подготовка сервера (Docker, брандмауэр, автообновления, ночные резервные копии), выкладка, проверка по HTTPS.
3. Откройте запуск → внизу **Summary**: там **адрес** сервера (например `https://203-0-113-10.sslip.io`) и версия. Откройте адрес — должно появиться веб-приложение Datascratch.
4. **Проверьте отпечаток ключа сервера, один раз.** В запуске, в шаге **SSH key and host key**, есть строка `Server host key (verify once)` с отпечатком `SHA256:…`. Он должен совпасть с тем, что вы видели в шаге 2.4. Совпал — всё в порядке. Чтобы GitHub дальше доверял только этому серверу, скопируйте строки под этим сообщением (начинаются с IP-адреса) в переменную: **Settings → Secrets and variables → Actions → Variables → New repository variable**, имя `DEPLOY_KNOWN_HOSTS`. Не совпал — не продолжайте и напишите Claude.

После этого каждый push в `main`, меняющий сервер, веб или инфраструктуру, выкладывается сам.

## Что происходит на сервере

| Что | Где |
| --- | --- |
| Всё приложение | `/opt/datascratch` (`docker-compose.yml`, `.env`, скрипты) |
| Секреты (пароль базы, `DS_KMS_KEY`, ключи токенов) | `/opt/datascratch/.env` — создаются **один раз на самом сервере**, в GitHub и в логи не попадают; при следующих выкладках не меняются |
| Брандмауэр | открыты только 22 (SSH), 80 и 443 (веб) |
| Обновления безопасности Ubuntu | ставятся автоматически каждый день |
| Резервные копии | каждую ночь в 03:17 → `/opt/datascratch/backups/`, хранятся 14 дней |
| Адрес | веб-приложение, API (`/v1`), синхронизация (WebSocket) и подключение ИИ-агентов (`/mcp`) — на одном домене; метрики наружу не отдаются |

**Сохраните `DS_KMS_KEY`.** В веб-консоли сервера: `grep DS_KMS_KEY /opt/datascratch/.env` — скопируйте значение в менеджер паролей. Без него ИИ-агенты потеряют доступ к блокнотам «для агентов», если сервер придётся восстанавливать на новой машине (ваши устройства продолжат работать).

**Копии вне сервера.** Ночные копии лежат на том же сервере. Чтобы они были и в другом месте (R-11), подключите Hetzner Storage Box или любое хранилище через `rclone` — см. `infra/README.md`, шаг 7 (на сервере: `apt install -y rclone && rclone config`, затем в `/opt/datascratch/.env` строка `BACKUP_RCLONE_REMOTE=storagebox:datascratch`).

## Какие адреса в интернете нужны серверу

Сервер ничего не скачивает с Docker Hub (из России он бывает недоступен): все образы, включая PostgreSQL, GitHub заранее перекладывает в свой реестр GHCR. Docker ставится из обычного репозитория Ubuntu. Серверу нужен доступ только к:

| Адрес | Зачем |
| --- | --- |
| `ghcr.io`, `pkg-containers.githubusercontent.com` | Скачать образы Datascratch при выкладке |
| Зеркало пакетов Ubuntu (обычно у хостинга, например `mirror.*` или `archive.ubuntu.com`, `security.ubuntu.com`) | Docker, брандмауэр, обновления безопасности |
| `acme-v02.api.letsencrypt.org` | Получить и продлевать HTTPS-сертификат |
| `sslip.io` (DNS) | Адрес без своего домена: `203-0-113-10.sslip.io` → ваш IP; используется браузерами и Let's Encrypt, сам сервер к нему не обращается |

Входящие подключения: SSH (22) — от GitHub Actions для выкладки, 80 и 443 — от пользователей и Let's Encrypt.

Если GHCR когда-нибудь окажется недоступен с сервера, Claude может переключить выкладку на зеркало `mirror.gcr.io` — напишите об этом.

## Память

Рассчитано на VPS с 2 ядрами и 4 ГБ: PostgreSQL ограничен 1 ГБ (`shared_buffers` 256 МБ), сервер — 1 ГБ, Caddy — 256 МБ; остальное — системе и кэшу диска. В простое всё вместе занимает около 400–500 МБ.

## Если выкладка не удалась

- Сервер **сам возвращается на предыдущую версию**, если новая не запустилась или не прошла проверку. Данные не трогаются.
- Красный крестик в Actions → откройте запуск, шаг с ошибкой подскажет причину. Частые:
  - `Missing secrets` (запуск пропущен, зелёный) — не добавлены `DEPLOY_HOST` / `DEPLOY_SSH_KEY`;
  - `not a valid private key` — секрет скопирован не целиком (нужны строки `BEGIN` и `END`);
  - `Server unreachable` — сервер выключен или закрыт порт SSH;
  - `Host key verification failed` — у сервера сменился ключ (переустановка): проверьте отпечаток, обновите переменную `DEPLOY_KNOWN_HOSTS` или удалите её.
- Откатить вручную: веб-консоль сервера → `/opt/datascratch/deploy.sh rollback`. Текущее состояние: `/opt/datascratch/deploy.sh status`.
- Изменения базы данных (миграции) только добавляют новое, поэтому откат на предыдущую версию безопасен.

## Подключить свой домен (по желанию)

1. У регистратора домена создайте запись **A**: имя, например, `notes` → IP сервера. Подождите 5–30 минут.
2. GitHub → **Settings → Secrets and variables → Actions → Variables** → **New repository variable**: имя `DS_DOMAIN`, значение `notes.ваш-домен.ru`.
3. **Actions → deploy → Run workflow**. Caddy сам получит сертификат для нового домена. Старый адрес `…sslip.io` перестанет обслуживаться — войдите в веб-приложении по новому адресу. Ссылки шеринга, созданные на старом адресе, нужно будет пересоздать.

## Адрес сервера для iPhone и iPad

Приложение для iOS узнаёт адрес сервера при сборке:

1. GitHub → **Settings → Secrets and variables → Actions → Variables** → **New repository variable**: имя `DS_SERVER_URL`, значение — адрес из Summary (например `https://203-0-113-10.sslip.io` или `https://notes.ваш-домен.ru`), без `/` в конце.
2. Выпустите новую сборку для TestFlight (`apps/ios/RELEASE.md`, «Как выпустить сборку»).

Веб-приложению ничего настраивать не нужно: оно открывается с того же адреса и само обращается к API на нём же.
